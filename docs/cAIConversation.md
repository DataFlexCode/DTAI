# cAIConversation Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

Provider-neutral conversation history for the DTAI library. A `cAIConversation` holds the turns of one conversation (user prompts, assistant replies, tool calls and tool results) in a form that every provider class (`cClaudeInterface`, `cChatGPTInterface`, `cGeminiInterface`, `cGrokInterface`) can replay. The same package also defines `cAITranscript`, an optional shared, human-readable log of a whole exchange.

Related classes: [cAITool](cAITool.md) · [cAIToolSet](cAIToolSet.md) · [cAIDialogue](cAIDialogue.md) (AI-to-AI)

Providers: [cAiInterface](cAiInterface.md) (base class) · [cClaudeInterface](cClaudeInterface.md) · [cChatGPTInterface](cChatGPTInterface.md) · [cGeminiInterface](cGeminiInterface.md) · [cGrokInterface](cGrokInterface.md)

## Overview

- History lives in a separate object, not in the provider. You attach a conversation to a provider with `Set phoConversation of <provider> to <conversation>`. When no conversation is attached, the provider uses its own internal default conversation (`phoDefaultConversation`).
- One conversation per view or task keeps histories apart, even though the provider objects (`ghoClaudeAI`, `ghoChatGPTAI`, `ghoGeminiAI`, `ghoGrokAI`) are global.
- A conversation can be moved to another provider mid-way. Turns made by another provider are replayed in their neutral form; provider-only extras (Claude thinking blocks, Gemini thought signatures, raw reply JSON) are dropped because they aren't portable. See `MessagesForProvider`.
- The conversation also holds the **tool confirmation state** of its last assistant turn (pending calls, results already run, approvals and declines), so two views that share a provider object don't interfere.
- The optional `psSystemPrompt` overrides the provider's `psSystemPrompt` for this conversation.

## Package and class hierarchy

```dataflex
Use cAIConversation.pkg   // normally not needed: ai.pkg already uses it
```

`ai.pkg` uses `cAIConversation.pkg`, and every provider package (`claudeai.pkg`, `chatgptai.pkg`, `geminiai.pkg`, `grokai.pkg`) uses `ai.pkg`. An application that uses a provider package can create `cAIConversation` objects without another `Use`.

```

 └─ cAIConversation
```

## Properties

| Property | Type | Default | Description |
|---|---|---|---|
| `paMessages` | `tAIMessage[]` | empty | The turns, oldest first. Use the procedures below to change it. |
| `psSystemPrompt` | `String` | `''` | System prompt for this conversation. When blank, the provider's `psSystemPrompt` is used (`EffectiveSystemPrompt` on the provider). |
| `psAssistantLabel` | `String` | `'Assistant'` | Speaker label for this conversation's assistant turns in the shared transcript. |
| `psUserLabel` | `String` | `'User'` | Speaker label for (non-relayed) user turns in the shared transcript. |
| `phoTranscript` | `Handle` | `0` | Optional `cAITranscript` that records the readable turns. Several conversations can share one. |
| `paPendingConfirmations` | `tAIToolCall[]` | empty | Calls of the last assistant turn waiting for `ApproveToolCall`/`DeclineToolCall`. Managed by the provider's tool loop. |
| `paHeldToolResults` | `tAIToolResult[]` | empty | Results already run for that turn, held until the pending calls are decided. Managed by the tool loop. |
| `paApprovedCallIds` | `String[]` | empty | Call ids approved with `ApproveToolCall`. Managed by the tool loop. |
| `paDeclinedCallIds` | `String[]` | empty | Call ids declined with `DeclineToolCall`. Managed by the tool loop. |
| `paDeclineReasons` | `String[]` | empty | Reasons, parallel to `paDeclinedCallIds`. Managed by the tool loop. |

The five confirmation properties are internal state; read `paPendingConfirmations`, and leave the rest to the provider.

## Procedures and functions

### Adding turns

| Signature | Description |
|---|---|
| `Procedure AddUserMessage String sText` | Adds a user turn. |
| `Procedure AddUserMessageWithAttachments String sText tAIAttachment[] Attachments` | Adds a user turn with attachments (base64 file data in `uBase64File`, `sMimeType`, optional `sFileID`). |
| `Procedure AddAssistantMessage String sText tAIToolCall[] ToolCalls String sProvider UChar[] ucProviderJson` | Adds an assistant turn. The tool loop calls this with the parsed reply; you rarely need it yourself (for example to seed a canned history). |
| `Procedure AddToolResults tAIToolResult[] Results` | Adds one `tool` turn with every result for the preceding assistant turn. Used in manual mode. |
| `Procedure AddRelayedMessage String sSpeaker String sText Boolean bPrefixLabel` | AI-to-AI: adds another participant's reply as a **user** turn of this conversation. With `bPrefixLabel` True the text sent to the model starts with `"<sSpeaker>: "`. Relayed turns are marked `bRelayed` and aren't recorded in the transcript a second time. |
| `Procedure AddMessage tAIMessage Msg` | Adds any prepared `tAIMessage` and records it in the transcript. The other Add procedures use it. |

### Reading and changing the history

| Signature | Description |
|---|---|
| `Function MessageCount Returns Integer` | Number of turns. |
| `Function MessageAt Integer iIndex Returns tAIMessage` | The turn at `iIndex` (0-based); an empty struct when out of range. |
| `Function LastMessage Returns tAIMessage` | The newest turn. |
| `Function LastAssistantText Returns String` | Text of the newest assistant turn that has text (`''` if none). |
| `Function HasUnansweredToolCalls Returns Boolean` | True when the last turn is an assistant turn with tool calls that have no results yet (manual mode, or a confirmation pause). |
| `Procedure SetMessages tAIMessage[] aMessages` | Replaces the whole history (for example after loading a saved conversation). Doesn't touch the transcript. |
| `Procedure RemoveLastMessage` | Removes the newest turn. |
| `Procedure ClearMessages` | Removes all turns **and** clears the tool confirmation state. Doesn't clear the transcript. |
| `Procedure ClearToolLoopState` | Clears only the confirmation state (pending calls, held results, approvals, declines). |
| `Function MessagesForProvider String sProvider Returns tAIMessage[]` | The turns as they are replayed to `sProvider` (`"claude"`, `"chatgpt"`, `"gemini"`, `"grok"`). Assistant turns made by another provider lose `ucProviderJson` and every call's `sProviderData`. |
| `Procedure RecordInTranscript tAIMessage Msg` | Adds a turn to `phoTranscript`. Skipped when there's no transcript, for relayed turns, for `tool` turns and for turns without text. Called by `AddMessage`. |

## cAITranscript

A readable log shared by one or more conversations. It's never sent to a model.

| Member | Description |
|---|---|
| `Property tAITranscriptEntry[] paEntries` | The entries (speaker, role, text, time). |
| `Procedure AddEntry String sSpeaker String sRole String sText` | Adds an entry stamped with `CurrentDateTime()`. |
| `Procedure ClearEntries` | Removes all entries. |
| `Function EntryCount Returns Integer` | Number of entries. |
| `Function AsMarkdown Returns String` | `**Speaker:**` followed by the text, entries separated by a blank line (CR/LF). |

| Member | Description |
|---|---|
| `eStopReason` | `AI_STOP_*` (see below). |
| `sText` | The reply text. |
| `ToolCalls` | Tool calls of the reply (manual mode). |
| `iToolIterations` | Round trips used by the tool loop. |
| `PendingConfirmations` | Calls waiting for approval when `eStopReason` is `AI_STOP_CONFIRMATION`. |
| `AssistantMessage` | The assistant turn as stored in the conversation. |

| Constant | Value | Meaning |
|---|---|---|
| `AI_STOP_UNKNOWN` | 0 | Not known. |
| `AI_STOP_END_TURN` | 1 | Normal final answer. |
| `AI_STOP_TOOL_CALLS` | 2 | The model wants tools run (manual mode returns here). |
| `AI_STOP_MAX_TOKENS` | 3 | Cut off by the token limit; calls in that turn aren't run. |
| `AI_STOP_CONTENT_FILTER` | 4 | Blocked or refused. |
| `AI_STOP_ERROR` | 5 | Transfer or API error; see `psLastError` on the provider. |
| `AI_STOP_CONFIRMATION` | 6 | The loop paused: calls need approval. |

## Working with the provider objects

These members of `cAiInterface` (`AppSrc\ai.pkg`) connect a provider to a conversation:

| Member | Description |
|---|---|
| `Property Handle phoConversation` | The attached conversation; `0` = use the internal default. |
| `Property Handle phoDefaultConversation` | The provider's internal default conversation. |
| `Function ActiveConversation Returns Handle` | `phoConversation`, else the default. Everything below works on this conversation. |
| `Procedure ClearConversation` | `ClearMessages` of the active conversation. |
| `Procedure AddUserMessage String sText` / `AddUserMessageWithAttachments` / `AddToolResults` | Forwarded to the active conversation. |
| `Function ConversationMessages Returns tAIMessage[]` | `MessagesForProvider` of the active conversation for this provider. |
| `Procedure SetConversationMessages tAIMessage[] aMessages` | `SetMessages` of the active conversation. |
| `Function EffectiveSystemPrompt Returns String` | The conversation's `psSystemPrompt`, else the provider's. |
| `Function Chat String sPrompt tAIAttachment[] Attachments Returns tAIResponse` | Adds the user turn and runs the tool loop. Attachments are optional. Unanswered calls of the previous turn are first answered as "not run". |
| `Function ContinueConversation Returns tAIResponse` | Runs the loop on the conversation as it is: after `AddToolResults` (manual mode), after `ApproveToolCall`/`DeclineToolCall`, or after `AddRelayedMessage`. |
| `Function paPendingConfirmations Returns tAIToolCall[]` | Read-only: the active conversation's pending calls. |
| `Procedure ApproveToolCall String sCallId` / `Procedure DeclineToolCall String sCallId String sReason` | Decide a pending call of the active conversation (reason optional). |
| `Procedure ClearToolLoopState` | Clears the active conversation's confirmation state. |
| `Property String[] paToolLoopLog` | Request and response JSON of every round trip of the last `Chat`/`ContinueConversation`. |

The tools themselves come from `phoToolSet` (a [cAIToolSet](cAIToolSet.md)), from `AddTool` plus `phoToolHandler`, or both; see [cAIToolSet](cAIToolSet.md#working-with-the-provider-objects).

### The tool loop in short

1. `Chat` adds the user turn; `RunConversation` sends the active conversation to the model.
2. The reply is added as an assistant turn. Without tool calls, the loop returns it.
3. With tool calls and `pbAutoExecuteTools` True, each call is run (or held for confirmation), one `tool` turn with every result is added, and the loop sends again.
4. The loop stops at a final answer, an error, a confirmation pause, `piMaxToolIterations` round trips, or the same call repeated `piMaxRepeatedToolCalls` times. On a limit, unanswered calls are answered as "not run" so the history stays valid.

With `pbAutoExecuteTools` False (manual mode) the loop returns `AI_STOP_TOOL_CALLS` with the calls in `Response.ToolCalls`; the app runs them, sends `AddToolResults`, then `ContinueConversation`.

## Tool confirmation state

Tools marked `pbRequiresConfirmation` (see [cAITool](cAITool.md#requires-confirmation)) are passed to the provider's `OnConfirmToolCall`. When it returns `AI_CONFIRM_DEFER` (the default when `pbSilentErrors` is True), the loop stops with `AI_STOP_CONFIRMATION`:

- The waiting calls are in `Response.PendingConfirmations` and in `paPendingConfirmations` of the conversation.
- Calls of the same turn that didn't need confirmation have already run; their results are held on the conversation.
- Attach the **same** conversation, call `ApproveToolCall`/`DeclineToolCall` for each pending call, then `ContinueConversation`. One `tool` turn with every result is added and the loop resumes.
- `ClearMessages` and a new `Chat` (which answers the pending calls as "not run") clear the state.

Because the state is on the conversation, a second conversation on the same provider neither sees nor clears another conversation's pending calls.

## Examples

### A conversation per view

The provider objects are global, so attach the view's conversation for the call and put the previous one back afterwards.

```dataflex
Use claudeai.pkg

Object oOrderAssistantView is a dbView
    Object oConversation is a cAIConversation
        Set psSystemPrompt to "You answer questions about customer orders. Keep answers short."
    End_Object

    Function AskAI String sPrompt Returns String
        Handle hoSaved
        tAIResponse Response

        Get phoConversation of ghoClaudeAI to hoSaved
        Set phoConversation of ghoClaudeAI to oConversation
        Get Chat of ghoClaudeAI sPrompt to Response
        Set phoConversation of ghoClaudeAI to hoSaved

        If (Response.eStopReason=AI_STOP_ERROR) Function_Return ("Error:"*psLastError(ghoClaudeAI))
        Function_Return Response.sText
    End_Function

    Procedure NewConversation
        Send ClearMessages of oConversation
    End_Procedure
End_Object
```

### Switching provider mid-conversation

```dataflex
tAIResponse Response
Set phoConversation of ghoClaudeAI to oConversation
Get Chat of ghoClaudeAI "Summarise order 1001." to Response
Set phoConversation of ghoClaudeAI to 0

// Gemini continues the same history; Claude's thinking blocks aren't sent to it
Set phoConversation of ghoGeminiAI to oConversation
Get Chat of ghoGeminiAI "Now write it as an e-mail." to Response
Set phoConversation of ghoGeminiAI to 0
```

### Confirmation with silent errors (deferred)

```dataflex
tAIResponse Response
tAIToolCall[] aPending
Integer i

Set pbSilentErrors of ghoChatGPTAI to True          // confirmations defer to the app
Set phoConversation of ghoChatGPTAI to oConversation
Get Chat of ghoChatGPTAI "Post a note: the server restarts at 18:00." to Response
If (Response.eStopReason=AI_STOP_CONFIRMATION) Begin
    Move Response.PendingConfirmations to aPending
    For i from 0 to (SizeOfArray(aPending)-1)
        // ask the user in your own UI; here every call is approved
        Send ApproveToolCall of ghoChatGPTAI aPending[i].sId
    Loop
    Get ContinueConversation of ghoChatGPTAI to Response
End
Set phoConversation of ghoChatGPTAI to 0
```

To decline instead: `Send DeclineToolCall of ghoChatGPTAI aPending[i].sId "Not during office hours."`. The model gets an error result and can answer accordingly.

### Manual mode

```dataflex
tAIResponse Response
tAIMessage LastMsg
tAIToolResult[] aResults
tAIToolResult Result
Integer i

Set pbAutoExecuteTools of ghoGrokAI to False
Set phoConversation of ghoGrokAI to oConversation
Get Chat of ghoGrokAI "What's the weather in Oslo?" to Response
If (Response.eStopReason=AI_STOP_TOOL_CALLS) Begin
    Get LastMessage of oConversation to LastMsg
    For i from 0 to (SizeOfArray(LastMsg.ToolCalls)-1)
        // RunToolCall uses phoToolSet / phoToolHandler; use your own code here if you like
        Get RunToolCall of ghoGrokAI LastMsg.ToolCalls[i] to Result
        Move Result to aResults[i]
    Loop
    Send AddToolResults of ghoGrokAI aResults
    Get ContinueConversation of ghoGrokAI to Response
End
Set phoConversation of ghoGrokAI to 0
Set pbAutoExecuteTools of ghoGrokAI to True
```

### AI-to-AI

Give each participant its **own** conversation: each side sees the other's replies as user turns, and provider extras aren't portable. A shared `cAITranscript` records the exchange once.

The easy way is [cAIDialogue](cAIDialogue.md) (`AppSrc\cAIDialogue.pkg`, used by `ai.pkg`), which manages the two conversations, relays each reply with `AddRelayedMessage`, and fills a transcript:

```dataflex
Object oDebate is a cAIDialogue
    Set psFirstLabel to "Claude"
    Set psSecondLabel to "Grok"
    Set psStopPhrase to "AGREED"     // optional: stop when a reply contains it
End_Object

Procedure RunDebate
    Integer iTurns
    String sText
    Set phoFirstAI of oDebate to ghoClaudeAI
    Set phoSecondAI of oDebate to ghoGrokAI
    Get Run of oDebate "Debate: should invoices be e-mailed or posted? Reply AGREED when you agree." 6 to iTurns
    Get AsMarkdown of (phoTranscript(oDebate)) to sText
End_Procedure
```

All `cAIDialogue` members, step-by-step running, per-side settings and the confirmation pause are described in [cAIDialogue](cAIDialogue.md); `AppSrc\AIDialogueDemo.vw` (View > AI Dialogue Demo in `ai.src`) is a working example.

The same by hand, with two conversations:

```dataflex
Object oTranscript is a cAITranscript
End_Object

Object oClaudeSide is a cAIConversation
    Set psAssistantLabel to "Claude"
    Set psUserLabel to "Moderator"
    Set phoTranscript to oTranscript
End_Object

Object oGrokSide is a cAIConversation
    Set psAssistantLabel to "Grok"
    Set phoTranscript to oTranscript
End_Object

Procedure OneRound String sOpening
    tAIResponse Response

    Set phoConversation of ghoClaudeAI to oClaudeSide
    Get Chat of ghoClaudeAI sOpening to Response
    Set phoConversation of ghoClaudeAI to 0

    // Claude's reply becomes Grok's user turn, prefixed "Claude: "
    Send AddRelayedMessage of oGrokSide "Claude" Response.sText True
    Set phoConversation of ghoGrokAI to oGrokSide
    Get ContinueConversation of ghoGrokAI to Response
    Set phoConversation of ghoGrokAI to 0

    Send AddRelayedMessage of oClaudeSide "Grok" Response.sText True
End_Procedure
```

## DataFlex 19.1 notes

- The package compiles and runs on DataFlex 19.1 and 25.0 (the offline tests run on both).
- On 19.1, `String` is OEM text, so text outside the OEM code page (emoji, CJK, some symbols) can't pass through `sText`, tool arguments or results. Raw provider replies are kept as UTF-8 in `ucProviderJson` (`UChar[]`), so exact replay isn't affected.
- On 19.1 `paToolLoopLog` entries are cut to `piMaxLogLength` (60000 characters by default; 0 = no limit on 20.0 and later), and only the newest `piMaxLogEntries` (40) are kept.
- `Chat`'s Attachments parameter is optional (`num_arguments`), which works on both versions.
