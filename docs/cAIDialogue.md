# cAIDialogue Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

Runs a conversation between two AI participants: AI-to-AI. Each participant is a provider object (`ghoClaudeAI`, `ghoGrokAI`, …) with its own [cAIConversation](cAIConversation.md). When one side answers, its reply is passed to the other side as a user turn, and a shared transcript records who said what. You can run several turns in one call or one turn at a time, give each side its own settings (model, persona, [tools](cAIToolSet.md)), and handle tool calls that need confirmation.

Related classes: [cAIConversation](cAIConversation.md) · [cAITool](cAITool.md) · [cAIToolSet](cAIToolSet.md) · [cAiInterface](cAiInterface.md) (provider base class)

Providers: [cClaudeInterface](cClaudeInterface.md) · [cChatGPTInterface](cChatGPTInterface.md) · [cGeminiInterface](cGeminiInterface.md) · [cGrokInterface](cGrokInterface.md)

Demo: `AppSrc\AIDialogueDemo.vw` (View > AI Dialogue Demo in `ai.src`), see [The demo view: AIDialogueDemo.vw](#the-demo-view-aidialoguedemovw).

## Overview

- **Two sides.** Side 0 is the *first* AI, side 1 the *second*. Each has a provider object (`phoFirstAI`, `phoSecondAI`), a label (`psFirstLabel`, `psSecondLabel`) and a conversation (`phoFirstConversation`, `phoSecondConversation`). Both sides may use the same provider object, for example Claude talking to Claude.
- **Separate histories.** A side's own replies are `assistant` turns in its conversation, and the other side's replies are `user` turns (added with `AddRelayedMessage`, optionally prefixed with the speaker's label). Provider-specific data (thinking blocks, Gemini signatures) stays in the conversation of the side that produced it.
- **The opening** (`Run` or `StartDialogue`) is a user message of the **first** side only. The second side first sees the first side's reply. If the second side needs the topic, put it in its system prompt (see [Per-side settings](#per-side-settings)).
- **The provider objects are not changed permanently.** During a turn the side's conversation is attached to its provider (`phoConversation`) and put back afterwards. Settings such as model or tool set can be changed for one turn in `OnBeforeSideTurn` and restored in `OnAfterSideTurn`.
- **Stops** on the stop phrase, an error, a content-filter stop, a confirmation pause, manual tool calls, `StopDialogue`, or when the requested number of turns is done.

## Procedures and functions

### Running

| Signature | Description |
|---|---|
| `Function Run String sOpening Integer iTurns Returns Integer` | Starts a new dialogue (`StartDialogue`) and runs up to `iTurns` turns (`ContinueDialogue`). Returns the turns completed. |
| `Procedure StartDialogue String sOpening` | Starts a new dialogue without running a turn: `ResetDialogue`, then `sOpening` becomes the first side's user message (and the first transcript entry). |
| `Function ContinueDialogue Integer iTurns Returns Integer` | Clears `pbStopped` and runs up to `iTurns` more turns, stopping early when `pbStopped` becomes True. Returns the turns completed by this call. |
| `Function StepDialogue Returns tAIResponse` | Clears `pbStopped` and runs exactly one turn. Use it for step-by-step UIs, and to go on after the stop phrase, `StopDialogue` or a decided confirmation. |
| `Function RunTurn Returns tAIResponse` | One turn without clearing `pbStopped` (used by the methods above). |
| `Procedure StopDialogue` | Sets `pbStopped`. Called from `OnDialogueTurn` it makes `ContinueDialogue`/`Run` stop after that turn. |
| `Procedure ResetDialogue` | Clears both conversations (including their pending confirmations) and the transcript; `piNextSide`, `piTurnsDone`, `pbStopped`, `peLastStopReason` and `psLastError` back to their defaults. |

### Sides

| Signature | Description |
|---|---|
| `Function SideAI Integer iSide Returns Handle` | `phoFirstAI` (0) or `phoSecondAI` (1). |
| `Function SideConversation Integer iSide Returns Handle` | `phoFirstConversation` (0) or `phoSecondConversation` (1). |
| `Function SideLabel Integer iSide Returns String` | `psFirstLabel` (0) or `psSecondLabel` (1). |
| `Function NextSideLabel Returns String` | Label of the side that answers next (during a pause: the side that is waiting). |
| `Procedure PrepareConversations` | Sets `psAssistantLabel` of each conversation to its side's label and `phoTranscript` of both to the dialogue's transcript. Sent before every turn. |

### Confirmation pause

| Signature | Description |
|---|---|
| `Function PendingConfirmations Returns tAIToolCall[]` | Calls of the next side waiting for a decision. |
| `Function IsWaitingForConfirmation Returns Boolean` | True when `PendingConfirmations` isn't empty. |
| `Procedure ApproveToolCall String sCallId` | Approves one pending call of the next side. |
| `Procedure DeclineToolCall String sCallId String sReason` | Declines one; `sReason` is optional and is sent to the model with the result. |
| `Procedure DecideToolCall String sCallId Boolean bApprove String sReason` | Used by the two above: attaches the side's conversation to its provider, sends `ApproveToolCall`/`DeclineToolCall` to the provider, and puts the provider's conversation back. |

## Events

| Signature | When |
|---|---|
| `Procedure OnBeforeSideTurn Integer iSide Handle hoAI` | Before the provider is called, with the side's conversation already attached to `hoAI`. Put per-side settings on `hoAI` here. |
| `Procedure OnAfterSideTurn Integer iSide Handle hoAI` | Right after the provider call (also after an error or pause), before the provider's own conversation is put back. Undo what `OnBeforeSideTurn` changed. |
| `Procedure OnDialogueTurn Integer iTurn String sSpeaker String sText` | After a completed turn (`AI_STOP_END_TURN` or `AI_STOP_MAX_TOKENS`), before the reply is relayed. `iTurn` is the new `piTurnsDone`. `StopDialogue` may be sent from here. |

## How a turn works

`RunTurn` does the following:

1. Takes the side in `piNextSide`, its provider and its conversation. If there is no provider object, the turn fails at once (`AI_STOP_ERROR`, `psLastError` = `"No AI object for <label>"`).
2. `PrepareConversations` (labels and transcript).
3. Saves the provider's `phoConversation`, attaches the side's conversation, and sends `OnBeforeSideTurn`.
4. `ContinueConversation` of the provider: the normal request and tool loop (see [cAIConversation](cAIConversation.md#working-with-the-provider-objects)). The side's system prompt is the conversation's `psSystemPrompt`, else the provider's.
5. If the turn stopped (anything but `AI_STOP_END_TURN`, `AI_STOP_MAX_TOKENS` or `AI_STOP_CONFIRMATION`) and the provider has an error (`HasError`), copies the provider's `psLastError` to the dialogue's `psLastError`, prefixed with the label. An `AI_STOP_ERROR` without a provider message gives `"<label>: The provider call failed."`. Sends `OnAfterSideTurn`, then puts the provider's conversation back.
6. Sets `peLastStopReason`. A turn that didn't end in `AI_STOP_END_TURN` or `AI_STOP_MAX_TOKENS` stops the dialogue here (`pbStopped`); a content-filter stop without an error message sets `psLastError` to `"<label>: the reply was blocked by the content filter."`; `piNextSide` doesn't change, so the same side goes on next time.
7. For a completed turn: `piTurnsDone` + 1, `OnDialogueTurn`, the side's last assistant text is relayed to the other side (`AddRelayedMessage`), `piNextSide` flips, and the stop phrase is checked.

## Stop conditions

| Condition | `peLastStopReason` | Turn counted / relayed | `psLastError` | How to go on |
|---|---|---|---|---|
| Turns requested by `Run`/`ContinueDialogue` done | `AI_STOP_END_TURN` | yes | `''` | `ContinueDialogue` or `StepDialogue` |
| Reply contains `psStopPhrase` | `AI_STOP_END_TURN` | yes | `''` | `StepDialogue`/`ContinueDialogue` (the phrase is checked again on later replies) |
| `StopDialogue` (e.g. from `OnDialogueTurn`) | of that turn | yes | `''` | `StepDialogue`/`ContinueDialogue` |
| Reply cut at max tokens | `AI_STOP_MAX_TOKENS` | yes (cut text is relayed) | `''` | continues normally |
| Provider or transfer error | `AI_STOP_ERROR` | no | `"<label>: <provider error>"`, or `"<label>: The provider call failed."` when the provider has no message | fix the cause, then `StepDialogue` (the same side retries) |
| Side without a provider object | `AI_STOP_ERROR` | no | `"No AI object for <label>"` | set `phoFirstAI`/`phoSecondAI` |
| Content filter / refusal | `AI_STOP_CONTENT_FILTER` | no | `"<label>: the reply was blocked by the content filter."` (the provider's error instead, if it reported one) | `StepDialogue` or start again |
| Tool call needs confirmation | `AI_STOP_CONFIRMATION` | no | `''` | approve/decline, then `StepDialogue`/`ContinueDialogue` |
| Manual tool mode (`pbAutoExecuteTools` False) | `AI_STOP_TOOL_CALLS` | no | `''` | run the calls on the side's conversation, then `StepDialogue` |
| Tool loop limit (`piMaxToolIterations`) or repeated call (`piMaxRepeatedToolCalls`) | `AI_STOP_TOOL_CALLS` | no | `"<label>: Tool loop limit reached"` (or `"...the same tool call was repeated"`) | `StepDialogue` (unanswered calls were cancelled, so the side answers again) |

## The transcript

`phoTranscript` is a `cAITranscript` (`AppSrc\cAIConversation.pkg`) shared by both conversations. A conversation adds an entry whenever it gets a message with text, except relayed messages and tool results, so every line of the dialogue appears once:

- the opening, with the first conversation's `psUserLabel` as speaker (default `'User'`; set it to `"Moderator"` or `"Topic"` if you like);
- each reply, with the side's label (`psAssistantLabel`, set from `psFirstLabel`/`psSecondLabel` by `PrepareConversations`);
- text that a model writes alongside a tool call ("Let me check the weather…") is also recorded, as a separate entry. Tool calls and results themselves are not.

| Member | Description |
|---|---|
| `paEntries` (`tAITranscriptEntry[]`) | The entries in order. |
| `Procedure AddEntry String sSpeaker String sRole String sText` | Adds an entry (`dtWhen` = now). |
| `Procedure ClearEntries` | Removes all entries (`ResetDialogue` does this). |
| `Function EntryCount Returns Integer` | Number of entries. |
| `Function AsMarkdown Returns String` | `**Speaker:**` + CR LF + text for each entry, separated by a blank line. |

```dataflex
Struct tAITranscriptEntry
    String   sSpeaker
    String   sRole        // 'user' or 'assistant'
    String   sText
    DateTime dtWhen
End_Struct
```

## Per-side settings

The dialogue only sets `phoConversation` on the provider. Everything else comes from the provider object, which is global and may be the same object for both sides. Use the conversation and the two events:

- **Persona / system prompt:** set `psSystemPrompt` of the side's conversation. It overrides the provider's `psSystemPrompt` and needs no restore.
- **Model, tool set, silent errors, tool settings:** set them in `OnBeforeSideTurn` and restore them in `OnAfterSideTurn`. Only one turn runs at a time, so one set of saved values is enough.

```dataflex
Object oDebate is a cAIDialogue
    Property Handle phoSavedToolSet 0
    Property String psSavedModel ''
    Property Boolean pbSavedSilent False

    Procedure OnBeforeSideTurn Integer iSide Handle hoAI
        Set phoSavedToolSet to (phoToolSet(hoAI))
        Set psSavedModel to (psModelId(hoAI))
        Set pbSavedSilent to (pbSilentErrors(hoAI))
        Set pbSilentErrors of hoAI to True
        If (iSide=0) Begin
            Set psModelId of hoAI to "claude-opus-5-5"
            Set phoToolSet of hoAI to oResearchTools
        End
        Else Begin
            Set psModelId of hoAI to "claude-haiku-5-5"
            Set phoToolSet of hoAI to 0
        End
    End_Procedure

    Procedure OnAfterSideTurn Integer iSide Handle hoAI
        Set phoToolSet of hoAI to (phoSavedToolSet(Self))
        Set psModelId of hoAI to (psSavedModel(Self))
        Set pbSilentErrors of hoAI to (pbSavedSilent(Self))
    End_Procedure
End_Object
```

## Tool calls and the confirmation pause

A side with a tool set (or `AddTool` tools) runs its tool calls inside its own turn. The tool loop is the provider's normal loop, so the calls and results stay in that side's conversation and the other side only sees the final reply.

For a tool with `pbRequiresConfirmation` the provider's `OnConfirmToolCall` decides. The default shows a Yes/No box, or defers when `pbSilentErrors` is True. A deferred call ends the turn with `AI_STOP_CONFIRMATION`:

- the dialogue stops (`pbStopped`), `piNextSide` stays on the waiting side, and no turn is counted;
- `PendingConfirmations` / `IsWaitingForConfirmation` show the waiting calls (the pending state lives in that side's conversation);
- `ApproveToolCall` / `DeclineToolCall` of the dialogue record the decision. Don't send them to the provider directly unless the side's conversation is attached;
- `StepDialogue` or `ContinueDialogue` resumes the same side: the decided calls are run or declined, the results go to the model, and the turn finishes.

See [cAITool, Requires confirmation](cAITool.md#requires-confirmation) for the provider side.

## Related structs and constants

`tAIResponse` (`AppSrc\ai.h`), returned by `StepDialogue` and `RunTurn`: `sText`, `eStopReason`, `ToolCalls`, `PendingConfirmations`, `iToolIterations`, `Usage` and more; see [cAIConversation](cAIConversation.md#related-structs-and-constants). `tAIToolCall` (`sId`, `sName`, `sArgumentsJson`) is described in [cAITool](cAITool.md#related-structs-and-constants).

| Constant | Value | In a dialogue |
|---|---|---|
| `AI_STOP_UNKNOWN` | 0 | No turn yet. |
| `AI_STOP_END_TURN` | 1 | Completed turn. |
| `AI_STOP_TOOL_CALLS` | 2 | Manual tool mode: calls waiting to be run. Stops. |
| `AI_STOP_MAX_TOKENS` | 3 | Completed turn, reply cut. |
| `AI_STOP_CONTENT_FILTER` | 4 | Blocked reply. Stops. |
| `AI_STOP_ERROR` | 5 | Error. Stops; see `psLastError`. |
| `AI_STOP_CONFIRMATION` | 6 | Waiting for approval. Stops. |

## Examples

### A debate in one call

```dataflex
Use claudeai.pkg
Use grokai.pkg

Object oDebate is a cAIDialogue
    Set psFirstLabel to "Claude"
    Set psSecondLabel to "Grok"
    Set psStopPhrase to "AGREED"
End_Object

Procedure RunDebate
    Integer iTurns
    String sText
    Set psSystemPrompt of (phoFirstConversation(oDebate)) to "You argue for e-mailed invoices. Max 60 words. Say AGREED when you agree."
    Set psSystemPrompt of (phoSecondConversation(oDebate)) to "The topic is how to send invoices. You argue for posted invoices. Max 60 words. Say AGREED when you agree."
    Set phoFirstAI of oDebate to ghoClaudeAI
    Set phoSecondAI of oDebate to ghoGrokAI
    Get Run of oDebate "Should our invoices be e-mailed or posted?" 8 to iTurns
    Get AsMarkdown of (phoTranscript(oDebate)) to sText
    If (psLastError(oDebate)<>'') Send Info_Box (psLastError(oDebate))
    Set Value of oResultEdit to sText
End_Procedure
```

### Step by step, updating a view after each turn

```dataflex
Object oDebate is a cAIDialogue
    Procedure OnDialogueTurn Integer iTurn String sSpeaker String sText
        Send AddToLog (sSpeaker+": "+sText)   // your own procedure in the view
    End_Procedure
End_Object

Procedure StartClicked
    Send StartDialogue of oDebate "Plan a three-day trip to Oslo."
End_Procedure

Procedure NextClicked
    tAIResponse Response
    Get StepDialogue of oDebate to Response
    If (Response.eStopReason=AI_STOP_CONFIRMATION) Send ShowPending
    Else If (psLastError(oDebate)<>'') Set Value of oErrorForm to (psLastError(oDebate))
    Else Set Value of oStatusForm to ("Next:"*NextSideLabel(oDebate))
End_Procedure
```

### Stopping from the event

```dataflex
Object oInterview is a cAIDialogue
    Set psFirstLabel to "Interviewer"
    Set psSecondLabel to "Candidate"

    // stop as soon as the interviewer has asked five questions
```

### Approving a tool call during a dialogue

```dataflex
// side 0 has a tool set with post_note (pbRequiresConfirmation) and
// pbSilentErrors True, so the call is deferred instead of showing a box
Procedure RunWithApproval
    Integer iTurns i iAnswer
    tAIToolCall[] aPending
    Get Run of oDebate "Agree on a note for the team board and post it." 6 to iTurns
    While (IsWaitingForConfirmation(oDebate))
        Get PendingConfirmations of oDebate to aPending
        For i from 0 to (SizeOfArray(aPending)-1)
            Get YesNo_Box (NextSideLabel(oDebate)*"wants to run"*aPending[i].sName+aPending[i].sArgumentsJson) to iAnswer
            If (iAnswer=MBR_Yes) Send ApproveToolCall of oDebate aPending[i].sId
            Else Send DeclineToolCall of oDebate aPending[i].sId "The user said no."
        Loop
        Get ContinueDialogue of oDebate (6-piTurnsDone(oDebate)) to iTurns
    Loop
End_Procedure
```

## The demo view: AIDialogueDemo.vw

`AppSrc\AIDialogueDemo.vw` (View > **AI Dialogue Demo** in `ai.src`) shows everything above:

- **Two participant panels**, each with a name, a provider (Claude, ChatGPT, Gemini, Grok), a model dropdown, a "Give this participant the demo tools" box, and a persona. The model dropdown works like the one in `AIToolCallTest.vw`: it is filled from the provider's `ModelList` (built-in list as fallback) and refreshed when the provider changes.
- **Topic, Max turns, Stop phrase** and **Prefix relayed text with the speaker's name** (`pbPrefixLabels`).
- **Start** begins a new dialogue and runs turns one by one (a `cTimer` between turns keeps the view responsive) until max turns, the stop phrase, an error or a pause. **Step** runs one turn and starts a dialogue first if needed. **Stop** stops after the current turn. **Reset** clears everything.
- **Approve pending / Decline pending** are enabled during a confirmation pause. After the decision the same participant finishes its turn, and a run started with Start continues.
- **Status** shows the turn, stop reason, tokens and who is next. **Error** shows `psLastError` (errors are silent).
- The **Transcript** tab shows the shared transcript; **Activity / tools** logs each turn's provider and model and every demo tool call.

How it uses the class:

- `ConfigureDialogue` copies the panels to `phoFirstAI`/`phoSecondAI`, the labels, `pbPrefixLabels` and `psStopPhrase` before every turn, and sets `psUserLabel` of the first conversation to "Topic", so the opening is recorded in the transcript under that name.
- Every turn is one `StepDialogue` call (`DoOneTurn`). With Start, `RunNextTurn` re-enables the `cTimer` after each turn until `pbStopped`, the max turns or a confirmation pause (`IsWaitingForConfirmation`). The status line uses `piTurnsDone`, the returned response (`eStopReason`, `Usage`, `iToolIterations`), `NextSideLabel` and `PendingConfirmations`.
- `OnBeforeSideTurn` → `ApplySideSettings` sets the side's model, the demo tool set (or none), `pbSilentErrors` True, `pbAutoExecuteTools` True and the conversation's `psSystemPrompt`. That prompt is the persona plus "You are <name>, talking with <other name>. The topic is: <topic>", so the second side knows the topic.
- `OnAfterSideTurn` → `RestoreSideSettings` puts the provider's tool set, silent-errors flag, auto-execute flag and model back.
- The demo tools come from `AppSrc\cAIDemoToolSet.pkg` (`cAIDemoToolSet`: `get_weather`, `calculate`, `lookup_customer`, `always_fails`, `post_note`). `AIToolCallTest.vw` uses the same set. `post_note` requires confirmation, so asking the participants to "post a note" shows the pause.

## DataFlex 19.1 notes

- `cAIDialogue` compiles and runs on DataFlex 19.1 and 25.0, and the offline tests (`DTAIOfflineTests.src`) cover it on both. The demo view is part of `ai.src`, which uses 20.0+ classes elsewhere and is compiled with 25.0 only.
- `cTimer` (used by the demo view) exists in 19.1 as well; the obsolete `DFTimer` isn't used.
- On 19.1, `String` is OEM text: replies with characters outside the OEM code page don't come through unchanged, and the transcript has the same limit.
- Long dialogues grow both conversations; every turn sends the side's whole history. Use `ResetDialogue`, or fewer turns, for long runs.
