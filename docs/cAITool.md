# cAITool Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

One application-defined tool (function) that an AI model can call. You describe the tool with a name, a description and a JSON Schema for its arguments, and write its `Execute` function in DataFlex. Tools are grouped in a [cAIToolSet](cAIToolSet.md), which you attach to a provider object; the provider's tool loop then runs the tool whenever the model asks for it and sends the result back.

## Overview

- A `cAITool` object is created **inside** a `cAIToolSet` object. In `End_Construct_Object` it registers itself with its parent (`Delegate Send RegisterAITool Self`), so the tool set needs no child-object enumeration.
- The tool's definition (`ToolDefinition`) is sent with every request; the same definition works for Claude, ChatGPT, Gemini and Grok.
- When the model calls the tool, the library parses the arguments into a `cJsonObject` and calls `Execute` with it. Whatever text `Execute` returns is sent to the model as the tool result. JSON text is recommended.
- Errors are results, not boxes: `ToolError`, invalid arguments, unknown tools and DataFlex errors raised inside `Execute` all reach the model as error results, so it can explain or retry.
- `pbRequiresConfirmation` makes the library ask before running the tool (for tools that change data, send mail, and so on).

## Properties

|---|---|---|---|
| `psName` | `String` | `''` | Tool name the model uses. Use `^[a-zA-Z0-9_-]{1,64}$` (letters, digits, `_`, `-`, up to 64 characters), the strictest rule across the providers. Names must be unique across the tool set and the provider's `AddTool` tools. |

| `pbEnabled` | `Boolean` | `True` | False hides the tool: it isn't sent with requests and isn't run. |
| `pbRequiresConfirmation` | `Boolean` | `False` | Ask before running; see [Requires confirmation](#requires-confirmation). |
| `pbToolErrorFlag` | `Boolean` | `False` | Set by `ToolError` during `Execute`; reset before each run. |
| `psToolErrorText` | `String` | `''` | The message passed to `ToolError`. |

## Procedures and functions

| Signature | Description |
|---|---|
| `Function Execute Handle hoArgs tAIToolCall ToolCall Returns String` | **Override this.** `hoArgs` is a `cJsonObject` holding the call's arguments (always a JSON object; the caller destroys it, so don't). `ToolCall` has the call id, name and argument text. Return the result text. The default implementation reports "Tool ... has no Execute function" as an error. |
| `Procedure ToolError String sMessage` | Call from `Execute` to mark the result as an error. The return value of `Execute` is then ignored and `sMessage` is sent instead. |
| `Procedure ResetToolError` | Clears `pbToolErrorFlag`/`psToolErrorText`. The tool set calls it before each run. |
| `Function ToolDefinition Returns tAIToolDefinition` | The definition sent to the model (name, description, schema, strict, requires confirmation). |
| `Procedure End_Construct_Object` | Registers the tool with its parent `cAIToolSet`. If you augment it, forward first. |

| Provider | Result | Error result |
|---|---|---|
| Claude | `tool_result` block with the text | same, with `is_error: true` |
| ChatGPT, Grok | `tool` message with the text | `tool` message with `{"error":"<message>"}` (Chat Completions has no error flag) |
| Gemini | `functionResponse` with `{"result": <JSON object or text>}` | `{"error": "<message>"}` |

## Working with the provider objects

Attach the tool set to a provider with `Set phoToolSet of <provider> to <tool set>`; see [cAIToolSet](cAIToolSet.md#working-with-the-provider-objects) for the full list of provider members (tool choice, loop limits, events, `AddTool`/`phoToolHandler`).

When the model calls a tool during `Chat` or `ContinueConversation` (see [cAIConversation](cAIConversation.md#working-with-the-provider-objects)), the provider:

1. looks up the definition (`FindToolDefinition`); unknown name → error result;
2. asks `OnConfirmToolCall` if `pbRequiresConfirmation` is set;
3. sends `OnBeforeToolCall` (return True to veto: error result);
4. normalizes the argument JSON (invalid → error result);
5. installs an error handler and sends `OnToolCall`, which calls `ExecuteToolCall` of the tool set, which calls your `Execute`;
6. turns a captured DataFlex error into an error result, cuts the result to `piMaxToolResultLength` (100000) characters, and sends `OnAfterToolCall`.

All results of one assistant turn go back in one tool turn of the conversation, in call order.

## Returning errors

Three ways a tool result becomes an error result (`bIsError` True):

1. **`ToolError`**: the normal way for expected problems (not found, invalid input, business rule).
2. **A DataFlex error inside `Execute`** (for example a database error): captured while the tool runs, so no error box appears; the model gets "The tool raised an error: <message>". This applies when the tool is run by the provider (`RunToolCall`); calling `ExecuteToolCall` of the tool set directly doesn't install the handler.
3. **Library checks**: unknown tool, disabled tool, invalid argument JSON, a veto in `OnBeforeToolCall`, or a declined confirmation.

Keep error messages short and useful to the model, for example "Customer C009 not found. Valid ids look like C001.".

## Requires confirmation

Set `pbRequiresConfirmation` to True for tools with side effects. Before such a tool runs, the provider calls its `OnConfirmToolCall`:

- **Default, `pbSilentErrors` False** (Windows apps): a Yes/No box shows the tool name and its arguments.
- **Default, `pbSilentErrors` True** (WebApps, batch): `AI_CONFIRM_DEFER`. The loop stops with `eStopReason = AI_STOP_CONFIRMATION`; the calls are in `Response.PendingConfirmations`. Call `ApproveToolCall`/`DeclineToolCall` for each, then `ContinueConversation`. The state is kept on the attached [cAIConversation](cAIConversation.md#tool-confirmation-state).
- Override `OnConfirmToolCall` in your own provider object for your own dialog or policy.

Other calls in the same turn still run; their results are held until the pending calls are decided, and every call always gets a result (declined calls get an error result).

## Examples

### A tool with a JSON schema

```dataflex
Use claudeai.pkg

Object oOrderTools is a cAIToolSet

    Object oLookupCustomer is a cAITool
        Set psName to "lookup_customer"
        Set psDescription to "Looks up a customer by id and returns name, city, balance and status."
        Set psParametersJson to '{"type":"object","properties":{"customer_id":{"type":"string","description":"Customer id, e.g. C001"}},"required":["customer_id"]}'

        Function Execute Handle hoArgs tAIToolCall ToolCall Returns String
            String sId
            Get MemberValue of hoArgs "customer_id" to sId
            Move (Uppercase(Trim(sId))) to sId

            Clear Customer
            Move sId to Customer.Id
            Find eq Customer by Index.1
            If (not(Found)) Begin
                Send ToolError ("Customer not found:"*sId)
                Function_Return ''
            End
            Function_Return ('{"id":"'+Trim(Customer.Id)+'","name":"'+Trim(Customer.Name)+'","balance":'+String(Customer.Balance)+'}')
        End_Function
    End_Object

End_Object

Procedure AttachTools
    Set phoToolSet of ghoClaudeAI to oOrderTools
End_Procedure
```

Escape text you put into JSON (quotes, backslashes, line breaks), or build the result with a `cJsonObject` and `Stringify` it:

```dataflex
Function Execute Handle hoArgs tAIToolCall ToolCall Returns String
    Handle hoResult
    String sJson
    Get Create (RefClass(cJsonObject)) to hoResult
    Send InitializeJsonType of hoResult jsonTypeObject
    Send SetMemberValue of hoResult "name" jsonTypeString (Trim(Customer.Name))
    Send SetMemberValue of hoResult "balance" jsonTypeDouble Customer.Balance
    Get Stringify of hoResult to sJson
    Send Destroy of hoResult
    Function_Return sJson
End_Function
```

### Optional, enum and number arguments

```dataflex
Object oCalculate is a cAITool
    Set psName to "calculate"
    Set psDescription to "Exact arithmetic on two numbers."
    Set psParametersJson to '{"type":"object","properties":{"a":{"type":"number"},"b":{"type":"number"},"operation":{"type":"string","enum":["add","subtract","multiply","divide"]}},"required":["a","b","operation"]}'

    Function Execute Handle hoArgs tAIToolCall ToolCall Returns String
        Number nA nB nResult
        String sOp
        Get MemberValue of hoArgs "a" to nA
        Get MemberValue of hoArgs "b" to nB
        Get MemberValue of hoArgs "operation" to sOp
        If (sOp="add") Move (nA+nB) to nResult
        Else If (sOp="subtract") Move (nA-nB) to nResult
        Else If (sOp="multiply") Move (nA*nB) to nResult
        Else If (sOp="divide") Begin
            If (nB=0) Begin
                Send ToolError "Division by zero is not allowed."
                Function_Return ''
            End
            Move (nA/nB) to nResult
        End
        Function_Return ('{"result":'+String(nResult)+'}')
    End_Function
End_Object
```

For an optional argument, check `HasMember of hoArgs "unit"` before reading it.

A custom confirmation policy in your own provider object:

```dataflex
Object oClaude is a cClaudeInterface
    Set phoToolSet to oOrderTools

    // supervisors may post notes without being asked; everything else uses the
    // default (Yes/No box, or defer when pbSilentErrors is True)
    Function OnConfirmToolCall tAIToolCall ToolCall Returns Integer
        Integer iAnswer
        If (ToolCall.sName="post_note" and gbSupervisor) Function_Return AI_CONFIRM_YES
        Forward Get OnConfirmToolCall ToolCall to iAnswer
        Function_Return iAnswer
    End_Function
End_Object
```

### A tool raising a DataFlex error

```dataflex
Object oArchiveOrders is a cAITool
    Set psName to "archive_orders"
    Set psDescription to "Moves orders older than the given year to the archive."
    Set psParametersJson to '{"type":"object","properties":{"year":{"type":"integer"}},"required":["year"]}'
    Set pbRequiresConfirmation to True

    Function Execute Handle hoArgs tAIToolCall ToolCall Returns String
        Integer iYear
        Get MemberValue of hoArgs "year" to iYear
        // a lock or database error raised here doesn't show a box while the
        // provider runs the tool; the model gets "The tool raised an error: ..."
        Send ArchiveOrdersBefore iYear
        Function_Return '{"archived":true}'
    End_Function
End_Object
```

## DataFlex 19.1 notes

- `cAITool` compiles and runs on DataFlex 19.1 and 25.0. Self-registration (`Delegate Send RegisterAITool Self`) is plain DataFlex and behaves the same on both.
- On 19.1, `String` is OEM text. Arguments and results that contain characters outside the OEM code page (emoji, CJK, some symbols) can't pass through `Execute`'s strings unchanged.
- String literals on 19.1 are limited to 255 characters. Split a long `psParametersJson` into concatenated parts, for example `Set psParametersJson to ('{"type":"object","properties":{...},' + '"required":["city"]}')`.
- Results are cut to `piMaxToolResultLength` (100000 characters) on every version; on 19.1 also keep in mind the argument size limit for long strings.
