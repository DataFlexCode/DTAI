# cAIToolSet Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

A collection of [cAITool](cAITool.md) objects. You create the tools as child objects of a `cAIToolSet`, attach the set to a provider object with `phoToolSet`, and the provider sends the tools' definitions with every request and runs them when the model calls them. One tool set can be shared by several providers and views.

Related classes: [cAITool](cAITool.md) · [cAIConversation](cAIConversation.md) · [cAIDialogue](cAIDialogue.md)

## Overview

- Each child `cAITool` registers itself with the set when it's constructed, so the set always knows its tools in creation order.
- `Definitions` returns the enabled tools' definitions; the provider sends them with every request (`AllToolDefinitions` adds them to the provider's own `AddTool` tools).
- `ExecuteToolCall` runs one call: it finds the tool, parses the arguments into a `cJsonObject`, calls the tool's `Execute`, and turns `ToolError`, unknown tools and invalid arguments into error results.
- `AppSrc\cAIDemoToolSet.pkg` (`cAIDemoToolSet`, used by `AIToolCallTest.vw` and `AIDialogueDemo.vw`) is a complete example: each tool is a small `cAITool` subclass, and the set creates one object of each.
- Tool sets hold no conversation state, so a single set can serve several views; per-view state (history, pending confirmations) lives on [cAIConversation](cAIConversation.md).

## Procedures and functions

| Signature | Description |
|---|---|
| `Procedure RegisterAITool Handle hoTool` | Adds a tool. Sent by each child `cAITool` from its `End_Construct_Object`; you only call it yourself for a tool object created elsewhere. |
| `Function ToolCount Returns Integer` | Number of registered tools (enabled or not). |
| `Function ToolByName String sName Returns Handle` | The **enabled** tool with this name, `0` if none. |
| `Function Definitions Returns tAIToolDefinition[]` | Definitions of all enabled tools (from each tool's `ToolDefinition`). |
| `Function ExecuteToolCall tAIToolCall ToolCall Returns tAIToolResult` | Runs one call. Fills `sCallId` and `sName`. Unknown or disabled tool, argument text that isn't a JSON object, and `ToolError` give an error result (`bIsError` True). Doesn't ask for confirmation and doesn't capture DataFlex errors: the provider's `RunToolCall` does both. |

### cAIToolErrorCapture (internal)

While a tool runs, the provider sets `Error_Object_Id` to its `cAIToolErrorCapture` object, so an error raised inside `Execute` doesn't show a box. Members: `piErrorCount`, `piErrorNumber`, `psErrorText` (the first error), `ClearCapturedErrors`, `Error_Report Integer iErrNum Integer iErrLine String sErrMsg`. You don't use it directly.

| Property | Type | Default | Description |
|---|---|---|---|
| `phoToolSet` | `Handle` | `0` | The attached `cAIToolSet`. |
| `phoToolHandler` | `Handle` | `0` | Object with `Function OnToolCall tAIToolCall ToolCall Returns tAIToolResult`, used for `AddTool` tools (see below). |
| `paTools` | `tAIToolDefinition[]` | empty | Tools added with `AddTool`. |

| `pbAutoExecuteTools` | `Boolean` | `True` | False = manual mode: `Chat` returns `AI_STOP_TOOL_CALLS` and the app runs the calls. |
| `piMaxToolIterations` | `Integer` | `8` | Maximum round trips per `Chat`/`ContinueConversation`. |
| `piMaxRepeatedToolCalls` | `Integer` | `3` | The same name and arguments this often in one loop stops it (0 = no check). |
| `piMaxToolResultLength` | `Integer` | `100000` | Results are cut to this length (0 = no limit). |
| `pbSilentErrors` | `Boolean` | `False` | True = no error boxes (check `HasError`/`psLastError`), and confirmations defer to the app. |

### Procedures and functions

| Signature | Description |
|---|---|
| `Function AllToolDefinitions Returns tAIToolDefinition[]` | Everything sent with a request: `paTools`, then the enabled tools of `phoToolSet`. A name in both is reported as `AI_ERR_TOOL_DEFINITION` and the `AddTool` version is kept. |
| `Function FindToolDefinition String sName Boolean ByRef bFound Returns tAIToolDefinition` | A definition by name from either source. |
| `Procedure SetToolChoice Integer eChoice String sToolName` | Sets `peToolChoice` and `psToolChoiceName`. |
| `Function RunToolCall tAIToolCall ToolCall Returns tAIToolResult` | Runs one call with every check (definition, `OnBeforeToolCall`, argument JSON, error capture, length limit, `OnAfterToolCall`). Doesn't ask for confirmation. Useful in manual mode. |
| `Function Chat String sPrompt tAIAttachment[] Attachments Returns tAIResponse` / `Function ContinueConversation Returns tAIResponse` | Run the tool loop on the active conversation; see [cAIConversation](cAIConversation.md#working-with-the-provider-objects). |
| `Procedure ApproveToolCall String sCallId` / `Procedure DeclineToolCall String sCallId String sReason` | Decide a call waiting for confirmation, then `ContinueConversation`. See [Requires confirmation](cAITool.md#requires-confirmation). |
| `Function paPendingConfirmations Returns tAIToolCall[]` | The active conversation's calls waiting for a decision. |

### Events (override in your own provider object)

| Signature | Description |
|---|---|
| `Function OnToolCall tAIToolCall ToolCall Returns tAIToolResult` | Dispatches a call: the tool set's tool with that name, else `phoToolHandler`, else an error result "No handler for tool ...". Override for a custom dispatcher. |
| `Function OnBeforeToolCall tAIToolCall ToolCall Returns Boolean` | Return True to veto a call (app-wide policy); the model gets an error result. |
| `Procedure OnAfterToolCall tAIToolCall ToolCall tAIToolResult Result` | After each call (logging, auditing). |
| `Procedure OnToolLoopIteration Integer iIteration` | Before each round trip (progress display). |
| `Function OnConfirmToolCall tAIToolCall ToolCall Returns Integer` | For tools with `bRequiresConfirmation`: `AI_CONFIRM_YES`, `AI_CONFIRM_NO` or `AI_CONFIRM_DEFER`. Default: Yes/No box, or defer when `pbSilentErrors` is True. |
| `Procedure OnAIError Integer iErr String sMessage` | Every reported error, including tool-loop errors. |

The provider objects are global. A view that changes tool settings for its own calls should save and restore them (as `AIToolCallTest.vw` does), or use its own provider object.

## Tools without a tool set: AddTool and phoToolHandler

For a few simple tools you can skip `cAITool` objects:

| Signature | Description |
|---|---|
| `Procedure AddTool String sName String sDescription String sParametersJson Boolean bRequiresConfirmation` | Adds or replaces a definition in `paTools`. Checks the name (`^[a-zA-Z0-9_-]{1,64}$`) and that the schema is a JSON object; problems are reported as `AI_ERR_TOOL_DEFINITION`. Blank schema = no parameters. `bRequiresConfirmation` is optional (default False). |
| `Procedure RemoveTool String sName` / `Procedure ClearTools` | Remove one or all `AddTool` tools. |
| `Function ToolIndex String sName Returns Integer` | Index in `paTools`, -1 if not there. |
| `Function ValidToolName String sName Returns Boolean` | The name rule above. |

The calls are run by the object in `phoToolHandler`:

```dataflex
Object oTimeTools is a cObject
    Function OnToolCall tAIToolCall ToolCall Returns tAIToolResult
        tAIToolResult Result
        If (ToolCall.sName="get_server_time") Move ('{"time":"'+String(CurrentDateTime())+'"}') to Result.sContent
        Else Begin
            Move True to Result.bIsError
            Move ("Unknown tool:"*ToolCall.sName) to Result.sContent
        End
        Function_Return Result
    End_Function
End_Object

Procedure AddTimeTool
    Send AddTool of ghoGeminiAI "get_server_time" "Current date and time on the server." ""
    Set phoToolHandler of ghoGeminiAI to oTimeTools
End_Procedure
```

`sCallId` and `sName` are filled in by the library, and DataFlex errors raised in the handler are captured like in a `cAITool`.

## Examples

### A tool set attached to a provider

```dataflex
Use chatgptai.pkg

Object oSupportTools is a cAIToolSet

    Object oGetWeather is a cAITool
        Set psName to "get_weather"
        Set psDescription to "Current weather for a city."
        Set psParametersJson to '{"type":"object","properties":{"city":{"type":"string"},"unit":{"type":"string","enum":["celsius","fahrenheit"]}},"required":["city"]}'

        Function Execute Handle hoArgs tAIToolCall ToolCall Returns String
            String sCity
            Get MemberValue of hoArgs "city" to sCity
            // ... call your weather service ...
            Function_Return ('{"city":"'+sCity+'","temperature":12,"conditions":"cloudy"}')
        End_Function
    End_Object

    Object oPostNote is a cAITool
        Set psName to "post_note"
        Set psDescription to "Posts a note to the team notice board."
        Set psParametersJson to '{"type":"object","properties":{"text":{"type":"string"}},"required":["text"]}'
        Set pbRequiresConfirmation to True

        Function Execute Handle hoArgs tAIToolCall ToolCall Returns String
            String sText
            Get MemberValue of hoArgs "text" to sText
            If (Trim(sText)="") Begin
                Send ToolError "The note text is empty."
                Function_Return ''
            End
            // ... save the note ...
            Function_Return '{"posted":true}'
        End_Function
    End_Object

End_Object

Procedure AskWithTools String sPrompt
    tAIResponse Response
    Set phoToolSet of ghoChatGPTAI to oSupportTools
    Get Chat of ghoChatGPTAI sPrompt to Response
    Showln Response.sText
End_Procedure
```

### One tool set, several providers and views

```dataflex
// each view keeps its own cAIConversation; the tools are shared
Set phoToolSet of ghoClaudeAI to oSupportTools
Set phoToolSet of ghoGeminiAI to oSupportTools
```

### Forcing a tool

```dataflex
tAIResponse Response
Send SetToolChoice of ghoClaudeAI AI_TOOLCHOICE_SPECIFIC "get_weather"
Get Chat of ghoClaudeAI "Oslo" to Response
Send SetToolChoice of ghoClaudeAI AI_TOOLCHOICE_AUTO ""
```

### An app-wide policy and an audit log

```dataflex
Object oClaude is a cClaudeInterface
    Set phoToolSet to oSupportTools
    Set piMaxToolIterations to 5

    // read-only users can't run tools that need confirmation
    Function OnBeforeToolCall tAIToolCall ToolCall Returns Boolean
        tAIToolDefinition Def
        Boolean bFound
        Get FindToolDefinition ToolCall.sName (&bFound) to Def
        Function_Return (bFound and Def.bRequiresConfirmation and gbReadOnlyUser)
    End_Function

    Procedure OnAfterToolCall tAIToolCall ToolCall tAIToolResult Result
        Send WriteAuditLog ToolCall.sName ToolCall.sArgumentsJson Result.bIsError
    End_Procedure
End_Object
```

### Running a call yourself (manual mode)

```dataflex
tAIResponse Response
tAIToolResult Result
tAIToolResult[] aResults
Integer i

Set pbAutoExecuteTools of ghoGrokAI to False
Get Chat of ghoGrokAI "What's the weather in Paris and Oslo?" to Response
If (Response.eStopReason=AI_STOP_TOOL_CALLS) Begin
    For i from 0 to (SizeOfArray(Response.ToolCalls)-1)
        Get ExecuteToolCall of oSupportTools Response.ToolCalls[i] to Result   // no confirmation, no error capture
        Move Result to aResults[i]
    Loop
    Send AddToolResults of ghoGrokAI aResults
    Get ContinueConversation of ghoGrokAI to Response
End
Set pbAutoExecuteTools of ghoGrokAI to True
```

Use `RunToolCall` of the provider instead of `ExecuteToolCall` when you want the provider's checks and error capture.

## DataFlex 19.1 notes

- `cAIToolSet`, `cAITool` and `cAIToolErrorCapture` compile and run on DataFlex 19.1 and 25.0. Tools register themselves (`Delegate Send RegisterAITool Self`), so no child-object enumeration is needed on either version.
- On 19.1, `String` is OEM text: tool arguments and results with characters outside the OEM code page can't pass through unchanged.
- String literals on 19.1 are limited to 255 characters; split long JSON schemas into concatenated parts.
- The error capture swaps `Error_Object_Id` while a tool runs, which works the same on both versions.
