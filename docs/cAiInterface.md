# cAiInterface Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

## Overview

`cAiInterface` (`AppSrc\ai.pkg`) is the base class of the DTAI provider classes. The class name in the source is `cAiInterface`. DataFlex names aren't case-sensitive, so `cAIInterface`, the spelling the provider packages use, is the same class.

It provides:

- **The HTTP layer:** it is a `cdtJsonHttpTransfer` (a `cJsonHttpTransfer` with extra logging and a timeout helper), so the subclasses post JSON over HTTPS.
- **The older single-request API:** `CreateRequest`, `MakeRequest`, `MakeRequestJSON` and `ModelList` are declared here and implemented by every provider.
- **Silent errors:** every provider and transfer error goes through `ReportAIError`. With `pbSilentErrors` True no box is shown and the error is kept in `psLastError` and related properties.
- **Tool calls:** a tool registry (`AddTool`, `phoToolSet`), tool choice, the confirmation hooks and the tool loop.
- **Conversations:** `Chat` and `ContinueConversation` work on a [cAIConversation](cAIConversation.md), with automatic tool execution, limits and a request/response log.

A provider subclass supplies the endpoint, the API key, the request and response formats (`BuildConversationRequest`, `ParseConversationResponse`) and the provider name. Everything about conversations and tools is shared, so the same application code works with Claude, ChatGPT, Grok and Gemini.

## Embedded Objects

- **`oDefaultConversation`** (`cAIConversation`): the conversation used when `phoConversation` is 0. Its handle is in `phoDefaultConversation`.
- **`oToolErrorCapture`** (`cAIToolErrorCapture`): installed as `Error_Object_Id` while a tool runs, so DataFlex errors inside a tool become error results. Its handle is in `phoToolErrorCapture`.

## Properties

### General
- **`psApiKey`** (String): API key. Each subclass sets it in `Construct_Object` from `ghoEnvironment`. Default `''`.
- **`paModels`** (tAIModel[]): the model list cached by `ModelList`. Set it to an empty array to make the next `ModelList` call reload it.
- **`psModelRequestJson`** (String): the last request JSON (set by `MakeRequest` and by every round trip of the tool loop, cut to `piMaxLogLength`).
- **`psModelResponseJson`** (String): the last response JSON, the same way.
- **`pLastCallStats`** (tRestCallStats): start, stop and elapsed time of the last `HttpPostJson`.
- **`psSystemPrompt`** (String): system prompt for conversation requests, used when the active conversation has no `psSystemPrompt` of its own. Default `''`.

Provider-specific properties such as `psHost`, `psModelId` and `piMaxTokens` are defined by the subclasses.

### Silent errors
- **`pbSilentErrors`** (Boolean): `False` (default) shows a box for each error. `True` shows nothing, and tool calls that need confirmation are deferred to the application (see [Confirmation](#tool-confirmation)).
- **`psLastError`** (String): message of the last error. `''` when the last call succeeded.
- **`piLastErrorNumber`** (Integer): `AI_ERR_*` of the last error (`AI_ERR_NONE` = no error).
- **`piLastHttpStatus`** (Integer): HTTP status code for `AI_ERR_TRANSFER` and `AI_ERR_API`, else 0.
- **`psLastErrorDetail`** (String): the box caption (for API errors usually the provider's error type).

### Tools
- **`paTools`** (tAIToolDefinition[]): tools added with `AddTool`.
- **`phoToolSet`** (Handle): an optional [cAIToolSet](cAIToolSet.md). Its enabled tools are sent with every conversation request. Default 0.
- **`phoToolHandler`** (Handle): an object with `Function OnToolCall tAIToolCall ToolCall Returns tAIToolResult` that runs `AddTool` tools. Default 0.
- **`peToolChoice`** (Integer): `AI_TOOLCHOICE_*`. Default `AI_TOOLCHOICE_AUTO`.
- **`psToolChoiceName`** (String): the tool for `AI_TOOLCHOICE_SPECIFIC`.
- **`pbParallelToolCalls`** (Boolean): allow several calls in one turn. Default `True`. Gemini ignores it.
- **`pbAutoExecuteTools`** (Boolean): `True` (default) runs tools automatically. `False` is manual mode: `Chat` returns `AI_STOP_TOOL_CALLS` and the application runs the calls.
- **`piMaxToolIterations`** (Integer): maximum round trips in one `Chat`/`ContinueConversation`. Default 8 (values below 1 count as 1).
- **`piMaxRepeatedToolCalls`** (Integer): the same tool name and arguments this many times in one loop stops it. Default 3; 0 = no check.
- **`piMaxToolResultLength`** (Integer): longer tool results are cut and end with `" ...[truncated]"`. Default 100000; 0 = no limit.

### Conversation
- **`phoConversation`** (Handle): the attached [cAIConversation](cAIConversation.md). 0 (default) uses `oDefaultConversation`.
- **`phoDefaultConversation`** (Handle): the internal default conversation.

### Tool loop log
- **`paToolLoopLog`** (String[]): request and response JSON of every round trip of the last `Chat`/`ContinueConversation`, in order: request 1, response 1, request 2, and so on. Cleared at the start of each call.
- **`piMaxLogLength`** (Integer): longer log entries (and `psModelRequestJson`/`psModelResponseJson` from the loop) are cut and end with `" ...[log entry truncated]"`. Default 0 (no limit) on DataFlex 20.0 and later, 60000 on 19.1, where strings are limited by the argument size.
- **`piMaxLogEntries`** (Integer): the oldest entries are dropped beyond this number. Default 40; 0 = keep all.

## Methods

### Older single-request API

These are declared here and implemented by every subclass. The base versions raise `DFERR_PROGRAM` "... not implemented".

#### `CreateRequest String sPrompt tAIAttachment[] Attachments Returns Handle`
Builds a provider request (a `cJsonObject`) for one prompt with optional attachments. The caller destroys it.

#### `MakeRequest Handle hoRequest Returns tAIResponse`
Sends a request built by `CreateRequest` and returns the unified response. On failure `eStopReason` is `AI_STOP_ERROR` and the error is in `psLastError`. Sets `psModelRequestJson` and `psModelResponseJson`. It doesn't destroy `hoRequest`.

#### `MakeRequestJSON Handle hoRequest Returns Handle`
Sends a request and returns the raw response `cJsonObject` (the caller destroys it), or 0 after reporting a transfer or API error. Each subclass checks the API key first (`CheckApiKeyExists`).

#### `ModelList Returns tAIModel[]`
Returns the provider's models. The first successful call is cached in `paModels`.

#### `CheckApiKeyExists Returns Boolean`
Clears the last error, then reports `AI_ERR_NO_API_KEY` ("Error API Key is not set, add to .env file") and returns False when `psApiKey` is blank.

#### `HttpPostJson String sHost String sFilePath Handle hoJsonRequest Boolean ByRef bOk Returns Handle`
Augmented to record `pLastCallStats`.

Inherited helpers used by the subclasses include `SetTimeout Integer iSeconds` (sets the WinINet receive timeout, process-wide), `DataReceived`, `psJsonTransferStatus`, `RemoveNullMembers` and, from the mixins, `Markdown2Html`, `ExtractJSON`, `MimeType` and `CreateAttachment String sFilename Returns tAIAttachment` (reads a file and base64-encodes it).

### Silent errors

#### `ReportAIError Integer iErr String sMessage String sCaption`
Records the error (`SetAIError`), sends `OnAIError`, and then, unless `pbSilentErrors` is True, shows it:

- `AI_ERR_NO_API_KEY` raises `DFERR_PROGRAM`;
- `AI_ERR_TRANSFER` uses `UserError`;
- everything else uses `Stop_Box` with `sCaption`.

#### `SetAIError Integer iErr String sMessage String sDetail`
Records an error without any UI and without `OnAIError`. It fills `piLastErrorNumber`, `psLastError` and `psLastErrorDetail`, and fills `piLastHttpStatus` (`ResponseStatusCode`) for transfer and API errors.

#### `ClearLastError`
Resets `piLastErrorNumber`, `psLastError`, `psLastErrorDetail` and `piLastHttpStatus`. It is sent at the start of every provider call (`CheckApiKeyExists`) and every `Chat`/`ContinueConversation`.

#### `HasError Returns Boolean`
True when `piLastErrorNumber` isn't `AI_ERR_NONE`.

#### Event `OnAIError Integer iErr String sMessage`
Sent for every reported error, silent or not. Override it for logging.

#### `ProviderName Returns String`
The short provider id stored in conversation history: `"claude"`, `"chatgpt"`, `"grok"` or `"gemini"`. The base class returns `''`.

### Tool registry

#### `AddTool String sName String sDescription String sParametersJson Boolean bRequiresConfirmation`
Adds a tool to `paTools`, or replaces it when the name is already there.

- `bRequiresConfirmation` is optional (default False).
- The name must match `^[a-zA-Z0-9_-]{1,64}$` (`ValidToolName`).
- The schema must be a JSON object; a blank schema means "no parameters" (`{"type":"object","properties":{}}`).
- Problems are reported as `AI_ERR_TOOL_DEFINITION` and the tool isn't added.

Calls to these tools are run by `phoToolHandler`.

#### `RemoveTool String sName` / `ClearTools`
Remove one or all `AddTool` tools.

#### `ToolIndex String sName Returns Integer`
Index in `paTools`, -1 if not there.

#### `ValidToolName String sName Returns Boolean`
The name rule above.

#### `SetToolChoice Integer eChoice String sToolName`
Sets `peToolChoice` and `psToolChoiceName`. `sToolName` is optional and is cleared when it isn't passed.

#### `AllToolDefinitions Returns tAIToolDefinition[]`
Everything sent with a conversation request: `paTools`, then the enabled tools of `phoToolSet`. A name in both is reported as `AI_ERR_TOOL_DEFINITION`, and the `AddTool` version is kept.

#### `FindToolDefinition String sName Boolean ByRef bFound Returns tAIToolDefinition`
A definition from either source.

#### `NormalizeJsonObjectText String sJson Boolean ByRef bOk String ByRef sError Returns String`
Parses JSON text and returns it re-stringified when it is an object (blank gives `{}`).

### Conversation

#### `Chat String sPrompt tAIAttachment[] Attachments Returns tAIResponse`
The main entry point. It:

1. clears the last error and the log;
2. answers any tool calls left unanswered in the conversation with "Not run: the conversation moved on before this call was answered.";
3. adds the user message (with optional attachments);
4. runs the tool loop until a final answer, an error, a confirmation pause (`AI_STOP_CONFIRMATION`) or, in manual mode, the first tool calls.

#### `ContinueConversation Returns tAIResponse`
Runs the tool loop on the conversation as it is: after `AddToolResults` (manual mode), after `ApproveToolCall`/`DeclineToolCall`, or after a relayed message ([cAIDialogue](cAIDialogue.md)).

#### `ActiveConversation Returns Handle`
`phoConversation`, or the default conversation.

#### Other conversation members
- `ClearConversation`, `AddUserMessage String sText`, `AddUserMessageWithAttachments String sText tAIAttachment[] Attachments` and `AddToolResults tAIToolResult[] Results` forward to the active conversation.
- `ConversationMessages Returns tAIMessage[]` is the active conversation's messages as this provider receives them (`MessagesForProvider`: replay data of other providers' turns is removed). `SetConversationMessages tAIMessage[] aMessages` replaces them.

#### `EffectiveSystemPrompt Returns String`
The active conversation's `psSystemPrompt`, else the provider's `psSystemPrompt`.

#### Provider hooks
`BuildConversationRequest tAIMessage[] Messages tAIToolDefinition[] Tools Returns Handle` and `ParseConversationResponse Handle hoResponse Returns tAIResponse` are implemented by each subclass. The base versions raise `DFERR_PROGRAM`.

### The tool loop

`Chat` and `ContinueConversation` use `RunConversation`:

1. If the last assistant turn has unanswered tool calls:
   - in manual mode, return `AI_STOP_TOOL_CALLS` with `ToolCalls`;
   - otherwise `ResolveToolCalls` runs, declines or holds each call. Calls that need confirmation are asked through `OnConfirmToolCall`. If any call is deferred, the results so far are held on the conversation and the loop returns `AI_STOP_CONFIRMATION` with `PendingConfirmations`.
2. `OnToolLoopIteration` (1, 2, …), then one round trip (`SendConversationTurn`):
   - `AllToolDefinitions` and `ConversationMessages` are passed to `BuildConversationRequest`;
   - the request is logged and sent with `MakeRequestJSON`;
   - the response is logged and parsed with `ParseConversationResponse`;
   - the assistant turn is added to the conversation.
3. Anything but `AI_STOP_TOOL_CALLS` (with calls) ends the loop.
4. Guards: the same name and arguments `piMaxRepeatedToolCalls` times, or `piMaxToolIterations` round trips. Either one answers the open calls with "Not run: …", reports `AI_ERR_TOOL_LOOP` ("Tool loop stopped: the same tool call was repeated" or "Tool loop limit reached") and returns. The returned `eStopReason` is still `AI_STOP_TOOL_CALLS`, so check `HasError`.

`tAIResponse.iToolIterations` holds the round trips used.

#### `RunToolCall tAIToolCall ToolCall Returns tAIToolResult`
Runs one call with every check. Each of these becomes an error result:

- an unknown or disabled tool ("Unknown tool: …");
- a veto from `OnBeforeToolCall` ("The application cancelled the call to …");
- arguments that aren't a JSON object ("Invalid JSON arguments: …");
- a DataFlex error raised inside the tool ("The tool raised an error: …").

It sets `sCallId`/`sName`, applies `piMaxToolResultLength` and sends `OnAfterToolCall`. It does **not** ask for confirmation, which makes it useful in manual mode.

#### `ResolveToolCalls tAIToolCall[] Calls Returns Boolean`, `CancelUnansweredToolCalls String sReason`, `ClearToolLoopState`
Internal parts of the loop. `ClearToolLoopState` clears the active conversation's confirmation state.

### Tool events

#### `OnToolCall tAIToolCall ToolCall Returns tAIToolResult`
Dispatches a call. It uses the tool set's tool with that name (`ExecuteToolCall`), else `OnToolCall` of `phoToolHandler`, else returns the error result "No handler for tool …". Override it for a custom dispatcher.

#### `OnBeforeToolCall tAIToolCall ToolCall Returns Boolean`
Return True to veto the call.

#### `OnAfterToolCall tAIToolCall ToolCall tAIToolResult Result`
After each call (logging, auditing).

#### `OnToolLoopIteration Integer iIteration`
Before each round trip (progress display).

#### `OnConfirmToolCall tAIToolCall ToolCall Returns Integer`
For tools with `bRequiresConfirmation`, return `AI_CONFIRM_YES`, `AI_CONFIRM_NO` or `AI_CONFIRM_DEFER`. The default shows a Yes/No box with the tool name and arguments (cut to 500 characters), or returns `AI_CONFIRM_DEFER` when `pbSilentErrors` is True.

### Tool confirmation

The state lives on the active conversation, so views with their own conversations don't interfere.

#### `paPendingConfirmations Returns tAIToolCall[]`
The active conversation's calls waiting for a decision. It is a function, not a property, of the provider.

#### `ApproveToolCall String sCallId`
Records an approval on the active conversation. Then `ContinueConversation` runs the approved call.

#### `DeclineToolCall String sCallId String sReason`
Records a decline. `sReason` is optional; the model gets the error result "The user declined to run <name>." followed by the reason.

Attach the same conversation (`phoConversation`) that paused before approving or declining. A new `Chat` instead answers the pending calls with "Not run: …".

## Usage Examples

### A chat with silent errors

```dataflex
Use claudeai.pkg

Procedure AskOnce
    tAIResponse Response
    Set pbSilentErrors of ghoClaudeAI to True
    Get Chat of ghoClaudeAI "Summarise our refund policy in one sentence." to Response
    If (Response.eStopReason=AI_STOP_ERROR or HasError(ghoClaudeAI)) ;
        Send Info_Box (psLastError(ghoClaudeAI)) "AI error"
    Else Send Info_Box Response.sText
End_Procedure
```

### The same code for any provider

```dataflex
Use claudeai.pkg
Use chatgptai.pkg
Use grokai.pkg
Use geminiai.pkg

Function AskProvider Handle hoAI String sQuestion Returns String
    tAIResponse Response
    Get Chat of hoAI sQuestion to Response
    Function_Return Response.sText
End_Function

// Get AskProvider ghoGeminiAI "What is DataFlex?" to sAnswer
```

### Tools added with AddTool and a handler object

```dataflex
Object oTimeTools is a cObject
    Function OnToolCall tAIToolCall ToolCall Returns tAIToolResult
        tAIToolResult Result
        Move ('{"time":"'+String(CurrentDateTime())+'"}') to Result.sContent
        Function_Return Result
    End_Function
End_Object

Procedure AddTimeTool
    Send AddTool of ghoGrokAI "get_server_time" "Current date and time on the server." ""
    Set phoToolHandler of ghoGrokAI to oTimeTools
End_Procedure
```

For larger tool collections use a [cAIToolSet](cAIToolSet.md) with [cAITool](cAITool.md) objects.

### Logging errors and tool calls

```dataflex
// WriteAppLog stands for your application's own logging procedure
Object oLoggedClaude is a cClaudeInterface
    Set pbSilentErrors to True

    Procedure OnAIError Integer iErr String sMessage
        Send WriteAppLog ("AI error"*String(iErr)+":"*sMessage)
    End_Procedure

    Procedure OnAfterToolCall tAIToolCall ToolCall tAIToolResult Result
        Send WriteAppLog ("tool"*ToolCall.sName*ToolCall.sArgumentsJson*If(Result.bIsError,"ERROR",""))
    End_Procedure
End_Object
```

### A confirmation pause

```dataflex
Procedure PostWithApproval
    tAIResponse Response
    Integer i
    Set pbSilentErrors of ghoClaudeAI to True   // defer instead of a Yes/No box
    Get Chat of ghoClaudeAI "Post 'Server restart at 6 PM' to the team board." to Response
    If (Response.eStopReason=AI_STOP_CONFIRMATION) Begin
        For i from 0 to (SizeOfArray(Response.PendingConfirmations)-1)
            Send ApproveToolCall of ghoClaudeAI Response.PendingConfirmations[i].sId
        Loop
        Get ContinueConversation of ghoClaudeAI to Response
    End
End_Procedure
```

### Showing the round trips of the last call

```dataflex
Procedure ShowToolLoopLog
    String[] aLog
    Integer i
    Get paToolLoopLog of ghoChatGPTAI to aLog
    For i from 0 to (SizeOfArray(aLog)-1)
        If (Mod(i,2)=0) Showln "--- request"
        Else Showln "--- response"
        Showln aLog[i]
    Loop
End_Procedure
```

## DataFlex 19.1 Notes

- `ai.pkg` and the provider packages compile and run on DataFlex 19.1 and 25.0, and the offline tests (`DTAIOfflineTests.src`) cover both.
- `piMaxLogLength` defaults to 60000 on 19.1, because strings are limited by the argument size. Raise `Set_Argument_Size` for large requests and responses.
