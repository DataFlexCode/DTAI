# cChatGPTInterface Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

## Overview

The `cChatGPTInterface` class provides a DataFlex interface to OpenAI's Chat Completions API (`v1/chat/completions`). It is part of the DTAI (Datatech AI Library) and inherits from [cAiInterface](cAiInterface.md) (declared as `cAIInterface`).

The class sends prompts with attachments (images, PDFs and text), reads the model list, and implements the request and response formats for conversations with tool calls (OpenAI "function calling"). Conversations, tools, the tool loop, confirmation and silent errors are implemented in [cAiInterface](cAiInterface.md).

The request builder (`cChatGPTRequest`) and response translator (`cChatGPTTranslator`) are also used by [cGrokInterface](cGrokInterface.md), because xAI's API is OpenAI-compatible.

## Properties

### Class Properties
- **`psHost`** (String): API endpoint host  
  Default: `"api.openai.com"`

- **`psApiKey`** (String): OpenAI API key (inherited)  
  Set in `Construct_Object` from `EnvironmentVariable(ghoEnvironment, "chatgpt-api-key")`

- **`psModelId`** (String): model identifier  
  Default: `"gpt-6-luna"` (`gpt-4.1-nano`, the earlier default, was shut down on Oct 23, 2026)

- **`piMaxTokens`** (Integer): maximum response tokens, sent as `max_tokens` or `max_completion_tokens` (see [Reasoning Models](#reasoning-models))  
  Default: `8192`

- **`psReasoningEffort`** (String): `reasoning_effort` for reasoning models, for example `"none"`, `"low"`, `"medium"` or `"high"`  
  Default: `''` (the model's default; with tools in the request `"none"` is sent)

- **`psTemperature`** (String): temperature  
  Default: `'1.0'`. **Not sent**: the `temperature` line in `cChatGPTRequest.ConstructRequest` is commented out, and the conversation request has no temperature.

## Methods

### Public Methods

#### `AddStandardHeaders`
Clears the headers and adds `Authorization: Bearer <psApiKey>`. Sets `psContentTypeSent` to `"application/json"`.

#### `MakeRequestJSON Handle hoRequest Returns Handle`
Sends a request to `v1/chat/completions` and returns the response JSON handle (the caller destroys it), or 0.

**Error Handling:**
- Checks the API key first (`AI_ERR_NO_API_KEY`)
- Transfer failures: `ReportAIError AI_ERR_TRANSFER`, caption "Transfer failed!"
- An `error` member in the response: `ReportAIError AI_ERR_API` with `error.message`, caption "API Error"
- Null members are removed from the response

#### `MakeRequest Handle hoRequest Returns tAIResponse`
Sends a request built by `CreateRequest` and returns the unified response (`sText`, `eStopReason`, `Usage`). Stores the request and response JSON in `psModelRequestJson`/`psModelResponseJson`. On failure `eStopReason` is `AI_STOP_ERROR`.

#### `CreateRequest String sPrompt tAIAttachment[] Attachments Returns Handle`
Builds a single-prompt request (the older API) with `ConstructRequest` of `oChatGPTRequest`: the prompt as a user message, and each attachment as one more user message with the text `"Attachment (<mime type>): <uBase64File>"`. Images and PDFs are therefore sent as base64 text, not as image or file parts; use `Chat` for real image and PDF parts. No system prompt is sent.

#### `CreateChatCompletion String sModel tChatGPTMessage[] Messages Integer iMaxTokens String sTemperature Returns tChatGPTResponse`
An older direct call with `tChatGPTMessage` structs (`role`, `content`). It uses its own request object, applies `max_completion_tokens` and `psReasoningEffort` for reasoning models, and reports transfer errors. It doesn't check the API key or an `error` object in the response.

#### `ModelList Returns tAIModel[]`
Calls `v1/models`. `display_name` is set to the id (OpenAI has no display name). Cached in `paModels`.

#### `IsReasoningModel String sModel Returns Boolean`
True for OpenAI reasoning models: names starting with `o` followed by a digit (`o1`, `o3-mini`, `o4-mini`, …) and `gpt-<N>…` with N of 5 or more, except names containing `-chat`. Override it for models the rule gets wrong.

#### `ApplyModelSettings Boolean bTools`
Sets the per-request members of `oChatGPTRequest` for `psModelId`. Called by `CreateRequest` (with False) and `BuildConversationRequest` (True when tools are sent).

#### `ProviderName Returns String`
Returns `"chatgpt"`.

### Conversation and Tool Methods

Inherited from [cAiInterface](cAiInterface.md): `Chat`, `ContinueConversation`, `AddTool`, `SetToolChoice`, `ApproveToolCall`, `DeclineToolCall`, the tool events and `OnAIError`.

#### `BuildConversationRequest tAIMessage[] Messages tAIToolDefinition[] Tools Returns Handle`
`ApplyModelSettings`, then `ConstructConversationRequest` of `oChatGPTRequest` with `psModelId`, `piMaxTokens`, the messages, the tools, `EffectiveSystemPrompt`, `peToolChoice`, `psToolChoiceName` and `pbParallelToolCalls`.

#### `ParseConversationResponse Handle hoResponse Returns tAIResponse`
Removes null members and calls `TranslateConversationResponse` of `oChatGPTTranslator`.

## Reasoning Models

OpenAI reasoning models reject `max_tokens`. When `IsReasoningModel(psModelId)` is True:

- `piMaxTokens` is sent as `max_completion_tokens`;
- `psReasoningEffort` is sent as `reasoning_effort` when not blank;
- when it is blank and the request has tools, `reasoning_effort: "none"` is sent, because the default `gpt-6-luna` supports function calling on Chat Completions only with that setting.

Other models get `max_tokens` and no `reasoning_effort`. Note that reasoning tokens count toward `max_completion_tokens`; raise `piMaxTokens` when answers come back empty with `AI_STOP_MAX_TOKENS`.

## Tool Call Mapping

How the neutral conversation maps to Chat Completions (`cChatGPTRequest.ConstructConversationRequest`):

| Neutral | Chat Completions request |
|---|---|
| System prompt | First message `{"role":"system","content":...}`, only when not blank |
| User message without attachments | `{"role":"user","content":"<text>"}` |
| User message with attachments | `content` is an array of parts: `text`; `image/*` as `{"type":"image_url","image_url":{"url":"data:<mime>;base64,..."}}`; `application/pdf` as `{"type":"file","file":{"filename":"document.pdf","file_data":"data:application/pdf;base64,..."}}`; `text/*` and `application/json` as a text part with `uBase64File` as is. Other types and `sFileID` attachments are skipped. |
| Assistant turn | Rebuilt from the neutral form: `content` (text) and `tool_calls` `[{"id","type":"function","function":{"name","arguments"}}]`. `arguments` is a JSON string. |
| Tool results | One `{"role":"tool","tool_call_id":...,"content":...}` message per result. Error results are sent as `{"error":"<message>"}`, because tool messages have no error flag. |
| `tAIToolDefinition` | `{"type":"function","function":{"name","description","parameters"}}`, plus `"strict": true` when `bStrict`. A blank or invalid schema becomes `{"type":"object","properties":{}}`. |
| `AI_TOOLCHOICE_AUTO` | `tool_choice` not sent (the API default is `auto`) |
| `AI_TOOLCHOICE_NONE` / `_REQUIRED` | `"none"` / `"required"` |
| `AI_TOOLCHOICE_SPECIFIC` | `{"type":"function","function":{"name":psToolChoiceName}}` (not sent when the name is blank) |
| `pbParallelToolCalls` False | `"parallel_tool_calls": false` |

`tools`, `tool_choice` and `parallel_tool_calls` are only sent when there are tools.

Response: `choices[0].message.tool_calls` become `tAIToolCall` (`sId` = `call_...`, `sArgumentsJson` = the normalised `arguments` string). `finish_reason` maps to `eStopReason`: `stop` → `AI_STOP_END_TURN`, `tool_calls`/`function_call` → `AI_STOP_TOOL_CALLS`, `length` → `AI_STOP_MAX_TOKENS`, `content_filter` → `AI_STOP_CONTENT_FILTER`. The raw message is kept in `AssistantMessage.ucProviderJson`, but the request builder always rebuilds assistant turns from the neutral form.

## Usage Examples

### A chat

```dataflex
Use ai.pkg
Use chatgptai.pkg

Procedure AskChatGPT
    tAIResponse Response
    Set pbSilentErrors of ghoChatGPTAI to True
    Set psSystemPrompt of ghoChatGPTAI to "Answer in one short paragraph."
    Get Chat of ghoChatGPTAI "What is a DataFlex DDO?" to Response
    If (HasError(ghoChatGPTAI)) Showln ("Error: " + psLastError(ghoChatGPTAI))
    Else Showln Response.sText
End_Procedure
```

### An image in a conversation

```dataflex
Procedure DescribeImage String sImagePath
    tAIAttachment[] Attachments
    tAIResponse Response
    Get CreateAttachment of ghoChatGPTAI sImagePath to Attachments[0]
    Send ClearConversation of ghoChatGPTAI
    Get Chat of ghoChatGPTAI "Describe this picture." Attachments to Response
    Showln Response.sText
End_Procedure
```

### A reasoning model with a set effort

```dataflex
Procedure UseReasoning
    tAIResponse Response
    Set psModelId of ghoChatGPTAI to "o4-mini"
    Set psReasoningEffort of ghoChatGPTAI to "low"
    Set piMaxTokens of ghoChatGPTAI to 16000   // reasoning tokens count too
    Get Chat of ghoChatGPTAI "Plan a 3-step data migration." to Response
End_Procedure
```

### Tools from a tool set, one call at a time

```dataflex
Procedure AskWithTools Handle hoToolSet
    tAIResponse Response
    Set phoToolSet of ghoChatGPTAI to hoToolSet
    Set pbParallelToolCalls of ghoChatGPTAI to False
    Get Chat of ghoChatGPTAI "Look up customer 42 and summarise their open orders." to Response
    Showln Response.sText
End_Procedure
```

### The single-request API

```dataflex
Procedure AskOnce
    Handle hoRequest
    tAIResponse Response
    Get CreateRequest of ghoChatGPTAI "Say hello in Dutch." to hoRequest
    Get MakeRequest of ghoChatGPTAI hoRequest to Response
    Send Destroy of hoRequest
    If (Response.eStopReason <> AI_STOP_ERROR) Showln Response.sText
End_Procedure
```

## Environment Setup

### API Key Configuration

The key is read from `ghoEnvironment` with the name `"chatgpt-api-key"` when the object is created:

1. Add `chatgpt-api-key={your key}` to the `{program}.env` file in the program folder, or
2. Set the Windows environment variable `chatgpt-api-key`, or
3. `Set psApiKey of ghoChatGPTAI to sKey` from your own settings.

Never put API keys in source code.

### Model Configuration

```dataflex
Set psModelId of ghoChatGPTAI to "gpt-6-luna"    // see ModelList for the ids your key can use
Set piMaxTokens of ghoChatGPTAI to 4096
Set psReasoningEffort of ghoChatGPTAI to ""       // model default ("none" with tools)
```

## Error Handling

All errors go through `ReportAIError` (see [cAiInterface](cAiInterface.md#silent-errors)). API errors use caption "API Error" (`psLastErrorDetail`) and the message from `error.message`; `piLastHttpStatus` has the HTTP status. With `pbSilentErrors` True nothing is shown.

## Known Limitations

- Only Chat Completions is used. The Responses API (`v1/responses`) is a later item in `tool_calls_plan.md`.
- `psTemperature` isn't sent.
- `CreateRequest` sends attachments as base64 text in extra user messages.
- In a conversation, attachments with an `sFileID` (OpenAI file ids) and types other than images, PDFs, text and JSON are skipped.
- Text attachments are sent as the content of `uBase64File` as is; `CreateAttachment` base64-encodes, so put plain text there for text types.
- `strict: true` needs `additionalProperties: false` and every property in `required`; leave `bStrict` False unless the schema follows those rules.
- `IsReasoningModel` is a name rule; override it for models it gets wrong.
- Streaming is not supported.
