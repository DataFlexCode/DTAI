# cClaudeInterface Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

## Overview

The `cClaudeInterface` class provides a DataFlex interface to Anthropic's Claude AI API (the Messages API, `v1/messages`). It is part of the DTAI (Datatech AI Library) and inherits from [cAiInterface](cAiInterface.md) (declared as `cAIInterface`), which in turn inherits from `cdtJsonHttpTransfer` and includes `cMarkdown_mixin` and `cBase64Attachment_mixin`.

The class handles communication with Claude models: text prompts, file attachments (images, PDFs and text), model lists, the beta Files API, and conversations with tool calls. Conversations, tools, the tool loop, confirmation and silent errors are implemented in [cAiInterface](cAiInterface.md); this class supplies the Claude request and response formats.

## Properties

### Class Properties
- **`psHost`** (String): API endpoint host  
  Default: `"api.anthropic.com"`

- **`psApiKey`** (String): Claude API key (inherited)  
  Set in `Construct_Object` from `EnvironmentVariable(ghoEnvironment,'claude-api-key')`

- **`psAnthropicVersion`** (String): value of the `anthropic-version` header  
  Default: `"2023-06-01"`

- **`psModelId`** (String): Claude model identifier  
  Default: `"claude-sonnet-5-5"` (`claude-sonnet-4-20250514`, the earlier default, was retired on June 15, 2026)

- **`piMaxTokens`** (Integer): maximum response tokens (`max_tokens`)  
  Default: `8192`

- **`pbEnableFilesApi`** (Boolean): adds the `anthropic-beta: files-api-2025-04-14` header to requests  
  Default: `False` (`True` in `cClaudeInterface_beta`)

### Inherited Properties

The general, silent error, tool, conversation and log properties are described in [cAiInterface](cAiInterface.md#properties). The ones used most with Claude:

- **`pbSilentErrors`**, **`psLastError`**, **`piLastErrorNumber`**, **`piLastHttpStatus`**, **`psLastErrorDetail`**: error handling
- **`psSystemPrompt`**: system prompt for conversation requests (the conversation's own prompt wins)
- **`phoConversation`**, **`phoToolSet`**, **`phoToolHandler`**, **`peToolChoice`**, **`pbParallelToolCalls`**, **`pbAutoExecuteTools`**, **`piMaxToolIterations`**
- **`psModelRequestJson`**, **`psModelResponseJson`**, **`paToolLoopLog`**: the JSON sent and received

**NOTE:** `cClaudeInterface` has the Files API methods (`UploadFile`, `ClaudeFileList`, `ClaudeFileMetaData`) itself. `UploadFile` always sends the beta header. Set `pbEnableFilesApi` to `True` (or use `cClaudeInterface_beta`) when a message refers to an uploaded file by its `file_id`.

## Methods

### Public Methods

#### `AddStandardHeaders String sContentType`
Adds required HTTP headers for Claude API requests.

**Parameters:**
- `sContentType` (optional): Content type header value (defaults to "application/json" if no arguments provided)

**Headers Added:**
- `Content-Type`: application/json (or specified type)
- `x-api-key`: Your Claude API key
- `anthropic-version`: `psAnthropicVersion`
- `anthropic-beta`: files-api-2025-04-14 (if `pbEnableFilesApi`)

**Implementation Notes:**
- Sets `pbClearHeaders` to `False`
- Clears existing headers before adding new ones
- Uses `num_arguments` to determine if content type was provided

#### `MakeRequestJSON Handle hoRequest Returns Handle`
Sends a JSON request to Claude and returns the response as a JSON handle.

**Parameters:**
- `hoRequest`: Handle to JSON request object

**Returns:**
- Handle to JSON response object (the caller destroys it)
- Returns `0` if the request fails

**Error Handling:**
- Checks the API key first (`CheckApiKeyExists`, `AI_ERR_NO_API_KEY`)
- Transfer failures: `ReportAIError AI_ERR_TRANSFER` with `TransferErrorDescription`, caption "Transfer failed!"
- API errors (`"type":"error"`): `ReportAIError AI_ERR_API` with the error message; the caption (`psLastErrorDetail`) is the error type, such as `invalid_request_error` or `overloaded_error`
- Destroys the response handle if an error is detected
- Removes null members from the response
- With `pbSilentErrors` True nothing is shown; check `HasError` and `psLastError`

**Implementation:**
- Uses `HttpPostJson` to send the request to the `v1/messages` endpoint
- Calls `AddStandardHeaders` automatically

#### `ModelList Returns tAIModel[]`
Retrieves available Claude models from the API.

**Returns:**
- Array of `tAIModel` structures containing:
  - `id`: Model identifier
  - `display_name`: Human-readable model name
  - `created_at`: Model creation timestamp
  - `type`: Model type

**Implementation:**
- Uses `HttpGetJson` to call the `v1/models` endpoint
- Converts the Claude model list to the unified `tAIModel` format
- The first successful result is cached in `paModels` and returned on later calls
- Errors go through `ReportAIError`

#### `CreateRequest String sPrompt [tAIAttachment[] Attachments] Returns Handle`
Creates a single-prompt Claude API request with optional attachments (the older API).

**Parameters:**
- `sPrompt`: Text prompt to send to Claude
- `Attachments` (optional): Array of file attachments

**Returns:**
- Handle to JSON request object ready for sending (the caller destroys it)

**Implementation:**
- Delegates to `CreateClaudeApiRequest` of `oClaudeRequest` (`model`, `max_tokens` and one user message)
- Uses an empty attachment array when no attachments are passed
- Doesn't send `psSystemPrompt`; use `Chat` for a system prompt

#### `MakeRequest Handle hoRequest Returns tAIResponse`
Sends a request and returns the unified response structure.

**Parameters:**
- `hoRequest`: Handle to JSON request object (not destroyed)

**Returns:**
- `tAIResponse` structure in unified format. `sText` holds the joined text, `eStopReason` the normalised stop reason, `Usage` the token counts.
- On failure `eStopReason` is `AI_STOP_ERROR` and the error is in `psLastError`.

**Implementation:**
- Stores the pretty-printed request and response in `psModelRequestJson` and `psModelResponseJson`
- Calls `MakeRequestJSON` internally
- Converts the Claude response to the unified format using `oClaudeTranslator`

#### `UploadFile String sFilename Returns String`
Uploads a file to the Files API (`v1/files`, multipart form data, beta header always sent) and returns its file id, or `''` on failure (`AI_ERR_TRANSFER`, `AI_ERR_API` or `AI_ERR_PARSE`). Put the id in `tAIAttachment.sFileID` to refer to the file in a message.

#### `ClaudeFileList Returns tClaudeModelList`
Lists uploaded files (`GET v1/files`). The declared return type is `tClaudeModelList`, but the function returns the parsed file list; see [Known Limitations](#known-limitations).

#### `ClaudeFileMetaData String sFileID Returns Boolean`
Reads the metadata of an uploaded file (`GET v1/files/<id>`). Marked TODO and untested in the source.

#### `ProviderName Returns String`
Returns `"claude"`, the provider id stored with assistant turns in a conversation.

### Conversation and Tool Methods

These are inherited from [cAiInterface](cAiInterface.md) and work the same for every provider:

- `Chat String sPrompt [tAIAttachment[] Attachments] Returns tAIResponse`
- `ContinueConversation Returns tAIResponse`
- `AddTool`, `RemoveTool`, `ClearTools`, `SetToolChoice`
- `ApproveToolCall`, `DeclineToolCall`, `paPendingConfirmations`
- Events `OnToolCall`, `OnBeforeToolCall`, `OnAfterToolCall`, `OnToolLoopIteration`, `OnConfirmToolCall`, `OnAIError`

`cClaudeInterface` implements the two provider hooks:

#### `BuildConversationRequest tAIMessage[] Messages tAIToolDefinition[] Tools Returns Handle`
Calls `CreateClaudeConversationRequest` of `oClaudeRequest` with the messages, the tools, `EffectiveSystemPrompt`, `peToolChoice`, `psToolChoiceName` and `pbParallelToolCalls`.

#### `ParseConversationResponse Handle hoResponse Returns tAIResponse`
Translates a Messages API response. It fills `ToolCalls` from the `tool_use` blocks, `eStopReason`, `sText` and `AssistantMessage`. `AssistantMessage.ucProviderJson` keeps the raw `{"role":"assistant","content":[...]}` for exact replay.

## Tool Call Mapping

How the neutral conversation maps to the Messages API (`cClaudeRequest.CreateClaudeConversationRequest`). Every request has `model` (`psModelId`), `max_tokens` (`piMaxTokens`) and `messages`; `tools` and `tool_choice` are only sent when there are tools.

| Neutral | Claude request |
|---|---|
| System prompt (`EffectiveSystemPrompt`) | `"system"`, only when not blank |
| `tAIToolDefinition` | `{"name","description","input_schema"}` plus `"strict": true` when `bStrict`. A blank or invalid schema is sent as `{"type":"object","properties":{}}`. |
| `AI_TOOLCHOICE_AUTO` | `tool_choice` left out, unless `pbParallelToolCalls` is False: then `{"type":"auto","disable_parallel_tool_use":true}` |
| `AI_TOOLCHOICE_NONE` | `{"type":"none"}` |
| `AI_TOOLCHOICE_REQUIRED` | `{"type":"any"}` |
| `AI_TOOLCHOICE_SPECIFIC` | `{"type":"tool","name":psToolChoiceName}` (`{"type":"auto"}` when the name is blank) |
| `pbParallelToolCalls` False | `"disable_parallel_tool_use": true` in `tool_choice` (not with `none`) |
| User message | `{"role":"user","content":[...]}` with a text block and attachment blocks |
| Assistant turn from Claude | Replayed from `ucProviderJson`, so `thinking` blocks and signatures are kept |
| Assistant turn from another provider | Rebuilt from its text and `tool_use` blocks (`id`, `name`, `input`) |
| Tool results | One `user` message with a `tool_result` block per result: `tool_use_id`, `content`, and `is_error: true` for errors |

Attachments in a conversation:

- `text/*` and `application/json`: a text block with the content of `uBase64File` as is (see [Known Limitations](#known-limitations)).
- `image/*`: an `image` block; `application/pdf`: a `document` block.
- Source: `{"type":"file","file_id":...}` when `sFileID` is set (needs `pbEnableFilesApi`), else `{"type":"base64","media_type":...,"data":...}`.
- Other types are skipped.

Response: `tool_use` blocks become `tAIToolCall` (`sId` = the `toolu_...` id, `sArgumentsJson` = the stringified `input`). `stop_reason` maps to `eStopReason`: `end_turn`/`stop_sequence` → `AI_STOP_END_TURN`, `tool_use` → `AI_STOP_TOOL_CALLS`, `max_tokens` → `AI_STOP_MAX_TOKENS`, `refusal` → `AI_STOP_CONTENT_FILTER`.

## Data Structures

### tAIAttachment
Used for file attachments (`ai.h`):
```dataflex
Struct tAIAttachment
    UChar[] uBase64File    // Base64 encoded file content
    String sMimeType       // MIME type (e.g., "image/png", "application/pdf")

End_Struct
```

### tAIResponse (Unified Response Structure)
Returned by `MakeRequest`, `Chat` and `ContinueConversation`. The most used members:

| Member | Description |
|---|---|
| `sText` | The joined text of the answer |
| `eStopReason` | `AI_STOP_*` (`AI_STOP_END_TURN`, `AI_STOP_TOOL_CALLS`, `AI_STOP_MAX_TOKENS`, `AI_STOP_CONTENT_FILTER`, `AI_STOP_ERROR`, `AI_STOP_CONFIRMATION`) |
| `ToolCalls` | Tool calls of the last turn |
| `PendingConfirmations` | Calls waiting for approval |
| `iToolIterations` | Round trips used by the tool loop |
| `Usage` | `iInputTokens`, `iOutputTokens`, `iCacheCreationInputTokens`, `iCacheReadInputTokens`, … |
| `sModel`, `sId`, `Choices` | Metadata and the content parts |

The full structure is described in [cAiInterface](cAiInterface.md#structs).

```dataflex
End_Struct
```

## Usage Examples

### Basic Text Prompt (Using Chat - Recommended)

```dataflex
Procedure AskSimpleQuestion
    tAIResponse Response

    Set pbSilentErrors of ghoClaudeAI to True
    Send ClearConversation of ghoClaudeAI
    Get Chat of ghoClaudeAI "What is the capital of France?" to Response

    If (HasError(ghoClaudeAI)) Showln ("Error: " + psLastError(ghoClaudeAI))
    Else Showln Response.sText
End_Procedure
```

### Basic Text Prompt (Using MakeRequest)

```dataflex
Procedure AskSingleRequest
    Handle hoRequest
    tAIResponse Response

    Get CreateRequest of ghoClaudeAI "What is the capital of France?" to hoRequest
    Get MakeRequest of ghoClaudeAI hoRequest to Response
    Send Destroy of hoRequest

    If (Response.eStopReason <> AI_STOP_ERROR) Showln Response.sText
End_Procedure
```

### Basic Text Prompt (Using MakeRequestJSON - Lower Level)

```dataflex
Procedure AskSimpleQuestionLowLevel
    String sPrompt sResponse
    Handle hoRequest hoResponse
    tClaudeResponse Response
    
    Move "What is the capital of France?" to sPrompt
    
    // Create request
    Get CreateRequest of ghoClaudeAI sPrompt to hoRequest
    
    // Send request
    Get MakeRequestJSON of ghoClaudeAI hoRequest to hoResponse
    
    If (hoResponse) Begin
        // Convert response to struct
        Set pbRequireAllMembers of hoResponse to False
        Get JsonToDataType of hoResponse to Response
        
        // Extract text response
        If (SizeOfArray(Response.content) > 0) Begin
            Move Response.content[0].text to sResponse
            Showln sResponse
        End
        
        Send Destroy of hoResponse
    End
    
    Send Destroy of hoRequest
End_Procedure
```

### Advanced Example with Attachments and Markdown Conversion

```dataflex
Procedure AskClaude
    String sPrompt sMarkdown sHtml
    tAIResponse Response
    tAIAttachment[] Attachments
    Integer iArgSize
    
    Get_Argument_Size to iArgSize
    Set_Argument_Size (1024*1024)
```

## Environment Setup

### API Key Configuration

The class retrieves the Claude API key from the global `ghoEnvironment` object using the name `'claude-api-key'` when the object is created.

**Setup Options:**
1. Add a line `claude-api-key={your key}` to your `{program}.env` file, in the folder of the program (`psProgramPath` of the workspace). Names in the file are not case-sensitive.
2. Set the Windows environment variable `claude-api-key`. It is used when the `.env` file doesn't have the name.
3. Set the key directly:

```dataflex
// Set API key programmatically (for example from your own settings table)
Set psApiKey of ghoClaudeAI to sKeyFromSettings
```

**Important:** The `ghoEnvironment` global object must be available before the `cClaudeInterface` instance is created. `claudeai.pkg` creates it when it doesn't exist yet. Never put API keys in source code or in files that are checked in.

### Model Configuration

You can customize the model and parameters:

```dataflex
// Change model (use ModelList for the ids your key can use)
Set psModelId of ghoClaudeAI to "claude-sonnet-5-5"

// Increase token limit
Set piMaxTokens of ghoClaudeAI to 16000

// Enable Files API

```

## Supported File Types

The class supports various file attachment types:

### Images
- **MIME Types**: `image/png`, `image/jpeg`, `image/gif`, `image/webp`
- **Processing**: Sent as an `image` block (base64, or a Files API `file_id`)

### Documents
- **MIME Types**: `application/pdf`
- **Processing**: Sent as a `document` block (base64, or a Files API `file_id`)

### Text Files
- **MIME Types**: `text/plain`, `text/markdown`, `text/csv`, `application/json`
- **Processing**: Sent as a text block containing `uBase64File` as is

In a conversation, other types are skipped. The older `CreateRequest` raises `DFERR_PROGRAM` "Unknown attachment type" for them.

## Error Handling

All errors go through `ReportAIError` of [cAiInterface](cAiInterface.md#silent-errors):

| Error | `piLastErrorNumber` | Shown (when `pbSilentErrors` is False) |
|---|---|---|
| No API key | `AI_ERR_NO_API_KEY` | `Error DFERR_PROGRAM` |
| Network, SSL, timeout | `AI_ERR_TRANSFER` | `UserError` |
| Claude error object (invalid key, rate limit, overloaded, invalid request) | `AI_ERR_API` | `Stop_Box`, caption = Claude error type |
| Unexpected upload response | `AI_ERR_PARSE` | `Stop_Box` |
| Tool loop limit / repeated call | `AI_ERR_TOOL_LOOP` | `Stop_Box` |
| Invalid tool definition | `AI_ERR_TOOL_DEFINITION` | `Stop_Box` |

`piLastHttpStatus` holds the HTTP status for transfer and API errors (for example 429 or 529).

### Example Error Handling

```dataflex
Procedure SafeClaudeRequest
    tAIResponse Response

    Set pbSilentErrors of ghoClaudeAI to True
    Get Chat of ghoClaudeAI "Your prompt here" to Response

    If (HasError(ghoClaudeAI)) Begin
        If (piLastHttpStatus(ghoClaudeAI) = 429) Showln "Rate limited, try again later"
        Else Showln ("Claude error: " + psLastError(ghoClaudeAI))
    End
    Else If (Response.eStopReason = AI_STOP_MAX_TOKENS) Showln "The answer was cut off; raise piMaxTokens"
    Else Showln Response.sText
End_Procedure
```

## Known Limitations

- Extended thinking isn't configured by the class (there is no thinking property). Thinking blocks returned by Claude are kept on replay through `ucProviderJson`.
- With extended thinking, Claude doesn't support a forced `tool_choice` (`any`/`tool`). The class doesn't fall back to `auto` automatically.
- `stop_reason: "max_tokens"` can cut off a `tool_use` block; such a turn is `AI_STOP_MAX_TOKENS` and the tools are not run.
- Text attachments are sent as the content of `uBase64File` as is. `CreateAttachment` base64-encodes every file, so a text file attached that way reaches Claude as base64 text. Put plain text in `uBase64File` for text types.
- The older `CreateClaudeApiRequest` sends `"type":"base64"` together with a `file_id` when `sFileID` is set; the conversation builder correctly sends `"type":"file"`. Use `Chat` for Files API attachments.
- `ClaudeFileList` is declared `Returns tClaudeModelList` but returns a `tClaudeFileList` value.
- Streaming and server tools (`pause_turn`) are not supported.

## Best Practices

### Memory Management
- Always destroy JSON request and response handles from `CreateRequest` and `MakeRequestJSON`
- Use appropriate argument size for large requests (`Set_Argument_Size`)
- Clear attachments after use

### Performance
- Reuse the global `ghoClaudeAI` object
- `ModelList` is cached in `paModels`
- Use appropriate token limits
- Keep conversations short or start a new one (`ClearConversation`) when the history is no longer needed; the whole history is sent with each request

### Security
- Store API keys in the `.env` file or environment variables, never in source code
- Validate file attachments before encoding
- Sanitize user input in prompts
- Mark tools that change data with `bRequiresConfirmation` and check arguments in `OnBeforeToolCall`
