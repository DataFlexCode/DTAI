# cGeminiInterface Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

## Overview

The `cGeminiInterface` class provides a DataFlex interface to Google's Gemini API (`generateContent` on `v1beta`). It is part of the DTAI (Datatech AI Library) and inherits from [cAiInterface](cAiInterface.md) (declared as `cAIInterface`).

The class sends prompts with attachments, reads the model list, and implements the Gemini request and response formats for conversations with tool calls (Gemini "function calling"): `systemInstruction`, `functionDeclarations`, `toolConfig`, `functionCall`/`functionResponse` parts and thought signatures. Conversations, tools, the tool loop, confirmation and silent errors are implemented in [cAiInterface](cAiInterface.md).

## Properties

### Class Properties
- **`psHost`** (String): API endpoint host  
  Default: `"generativelanguage.googleapis.com"`

- **`psApiKey`** (String): Gemini API key (inherited)  
  Set in `Construct_Object` from `EnvironmentVariable(ghoEnvironment,'gemini-api-key')`

- **`psModelId`** (String): model name **including** the `models/` prefix, as returned by `ModelList`  
  Default: `"models/gemini-3.8-flash"` (`gemini-2.5-flash` is deprecated)

- **`piMaxTokens`** (Integer): `generationConfig.maxOutputTokens` for conversation requests, unless `pGenerationConfig.iMaxOutputTokens` is set  
  Default: `8192`

- **`pGenerationConfig`** (tGenerationConfig): optional generation settings  
  ```dataflex

      Number  nTemperature
      Number  nTopP
  ```

  In a conversation request only the members above 0 are sent. See [Known Limitations](#known-limitations) for the older `CreateRequest`.

- **`piCallSequence`** (Integer): numbers the ids generated for function calls that come without an id (`gemini-call-<n>`)  
  Default: `0`

## Methods

### Public Methods

#### `AddStandardHeaders`
Clears the headers and sets `psContentTypeSent` to `"application/json"`. The API key is not a header; it is sent in the URL.

#### `MakeRequestJSON Handle hoRequest Returns Handle`
Posts to `v1beta/<psModelId>:generateContent?key=<psApiKey>` and returns the response JSON handle (the caller destroys it), or 0.

**Error Handling:**
- Checks the API key first (`AI_ERR_NO_API_KEY`)
- Transfer failures: `ReportAIError AI_ERR_TRANSFER`, caption "Transfer failed!"
- An `error` member: `ReportAIError AI_ERR_API` with `error.message`, caption "API Error"
- A reply that isn't JSON: `ReportAIError AI_ERR_PARSE` "Response was not JSON: …" (first 1000 characters)
- Null members are removed from the response

#### `MakeRequest Handle hoRequest Returns tAIResponse`
Sends a request built by `CreateRequest` and returns the unified response. Stores the request and response JSON in `psModelRequestJson`/`psModelResponseJson`. On failure `eStopReason` is `AI_STOP_ERROR`.

#### `CreateRequest String sPrompt tAIAttachment[] Attachments Returns Handle`
Builds a single-prompt request (the older API) with `CreateGeminiApiJsonRequest`: a text part, and each attachment as an `inlineData` part (`mimeType`, base64 `data`), all in one user content. No system instruction is sent.

#### `ModelList Returns tAIModel[]`
Calls `v1beta/models?key=…`. `id` is the model `name` (for example `models/gemini-3.8-flash`) and `display_name` the `displayName`. Cached in `paModels`.

#### `ProviderName Returns String`
Returns `"gemini"`.

### Conversation and Tool Methods

Inherited from [cAiInterface](cAiInterface.md): `Chat`, `ContinueConversation`, `AddTool`, `SetToolChoice`, `ApproveToolCall`, `DeclineToolCall`, the tool events and `OnAIError`.

#### `BuildConversationRequest tAIMessage[] Messages tAIToolDefinition[] Tools Returns Handle`
`CreateGeminiConversationRequest` of `oGeminiRequest` with the messages, the tools, `EffectiveSystemPrompt`, `peToolChoice`, `psToolChoiceName`, `pGenerationConfig` and `piMaxTokens`.

#### `ParseConversationResponse Handle hoResponse Returns tAIResponse`
Translates a `generateContent` response:

- `usageMetadata` fills `Usage` (`promptTokenCount`, `candidatesTokenCount`, `totalTokenCount`; also copied to `iInputTokens`/`iOutputTokens`); `modelVersion` and `responseId` fill `sModel` and `sId`.
- No candidates and a `promptFeedback.blockReason`: `eStopReason` is `AI_STOP_CONTENT_FILTER`.
- `functionCall` parts become `tAIToolCall`:
  - `sId` is Gemini's `id`, or `gemini-call-<n>` when there is none;
  - `sArgumentsJson` is the stringified `args`;
  - the part's `thoughtSignature` is kept in `sProviderData`.
- Text parts make up `sText`, except thought summaries (`"thought": true`).
- The raw candidate content `{"role":"model","parts":[...]}` is kept in `AssistantMessage.ucProviderJson`.
- `finishReason` is mapped by `AIFinalizeResponse`; any `functionCall` part makes it `AI_STOP_TOOL_CALLS`.

#### `JsonMemberText Handle hoJson String sMember Returns String`
Helper: a member's value as text, `''` when missing.

## Tool Call Mapping

How the neutral conversation maps to `generateContent` (`cGeminiRequest.CreateGeminiConversationRequest`):

| Neutral | Gemini request |
|---|---|
| System prompt | `"systemInstruction": {"parts":[{"text":...}]}`, only when not blank |
| User message | A `user` content with a `text` part and attachment parts |
| Assistant turn from Gemini | The raw `parts` from `ucProviderJson`, replayed exactly (keeps `thoughtSignature`) |
| Assistant turn rebuilt | A `model` content with a `text` part and `functionCall` parts (`name`, `args` object). The `id` is only sent when Gemini supplied it, and `thoughtSignature` from `sProviderData` when the turn came from Gemini. |
| Tool results | A `user` content with one `functionResponse` part per result, in call order: `{"name", "response": {"result": <object or text>}}`, or `{"error": "<message>"}` for error results. The name comes from the result, else from the matching call by id, then by position. The `id` is only sent back when Gemini supplied it. |
| Consecutive turns with the same role | Merged into one content, because Gemini wants `user` and `model` turns to alternate |
| `tAIToolDefinition` | `"tools": [{"functionDeclarations": [{"name","description","parametersJsonSchema"}]}]`. A blank or invalid schema sends the function without parameters. `bStrict` isn't used. |
| `AI_TOOLCHOICE_AUTO` | `toolConfig` not sent (the API default is `AUTO`) |
| `AI_TOOLCHOICE_NONE` | `"toolConfig": {"functionCallingConfig": {"mode":"NONE"}}` |
| `AI_TOOLCHOICE_REQUIRED` | `mode: "ANY"` |
| `AI_TOOLCHOICE_SPECIFIC` | `mode: "ANY"` plus `"allowedFunctionNames": [psToolChoiceName]` |
| `pbParallelToolCalls` | Ignored (no Gemini switch; say it in the prompt if needed) |
| `piMaxTokens` / `pGenerationConfig` | `generationConfig`: `maxOutputTokens` (`iMaxOutputTokens`, else `piMaxTokens`), `temperature`, `topP`, `topK` when above 0 |

Attachments in a conversation:

- `text/*` and `application/json`: a `text` part with `uBase64File` as is;
- with `sFileID` set: `{"fileData": {"mimeType", "fileUri": sFileID}}`;
- otherwise: `{"inlineData": {"mimeType", "data"}}` with the base64 content.

### Thought signatures

Gemini thinking models attach a `thoughtSignature` to parts, and Gemini 3 rejects (HTTP 400) a function-calling turn whose signature isn't sent back. The class keeps it two ways: the raw model content is replayed from `ucProviderJson`, and each call's signature is also in `tAIToolCall.sProviderData` for rebuilt turns. Don't edit the assistant turns of a Gemini conversation in a way that drops `ucProviderJson`.

### Call ids

`functionCall.id` is optional. When Gemini doesn't send one, the class makes `gemini-call-<n>` (counted by `piCallSequence`) so the tool loop and confirmation can tell calls apart. These ids are never sent to Gemini; results are matched by name and order instead.

## Usage Examples

### A chat

```dataflex
Use geminiai.pkg

Procedure AskGemini
    tAIResponse Response
    Set pbSilentErrors of ghoGeminiAI to True
    Get Chat of ghoGeminiAI "Give three tips for naming DataFlex tables." to Response
    If (HasError(ghoGeminiAI)) Showln ("Error: " + psLastError(ghoGeminiAI))
    Else Showln Response.sText
End_Procedure
```

### Generation settings

```dataflex
Procedure ConfigureGemini
    tGenerationConfig Config
    Move 2048 to Config.iMaxOutputTokens
    Move 0.2 to Config.nTemperature
    Set pGenerationConfig of ghoGeminiAI to Config
    Set psModelId of ghoGeminiAI to "models/gemini-3.8-flash"
End_Procedure
```

### Forcing one tool

```dataflex
Procedure ForceLookup Handle hoToolSet
    tAIResponse Response
    Set phoToolSet of ghoGeminiAI to hoToolSet
    Send SetToolChoice of ghoGeminiAI AI_TOOLCHOICE_SPECIFIC "lookup_customer"
    Get Chat of ghoGeminiAI "Who is customer 3?" to Response
    // the forced choice also applies to the next round trip; reset it afterwards
    Send SetToolChoice of ghoGeminiAI AI_TOOLCHOICE_AUTO
    Showln Response.sText
End_Procedure
```

With `AI_TOOLCHOICE_SPECIFIC` or `AI_TOOLCHOICE_REQUIRED` every round trip of the loop forces a call, so the loop can end at `piMaxToolIterations` without a text answer. Prefer `AI_TOOLCHOICE_AUTO` with a clear tool description for normal use.

### A PDF as inline data

```dataflex
Procedure SummarisePdf String sPdfPath
    tAIAttachment[] Attachments
    tAIResponse Response
    Get CreateAttachment of ghoGeminiAI sPdfPath to Attachments[0]
    Send ClearConversation of ghoGeminiAI
    Get Chat of ghoGeminiAI "Summarise this document in five bullet points." Attachments to Response
    Showln Response.sText
End_Procedure
```

## Environment Setup

### API Key Configuration

The key is read from `ghoEnvironment` with the name `'gemini-api-key'` when the object is created:

1. Add `gemini-api-key={your key}` to the `{program}.env` file in the program folder, or
2. Set the Windows environment variable `gemini-api-key`, or
3. `Set psApiKey of ghoGeminiAI to sKey` from your own settings.

Never put API keys in source code. Because the key is part of the request URL, also keep it out of logs (see [Known Limitations](#known-limitations)).

## Error Handling

All errors go through `ReportAIError` (see [cAiInterface](cAiInterface.md#silent-errors)). API errors use caption "API Error" and `error.message`; `piLastHttpStatus` has the HTTP status. A blocked prompt is not an error: `eStopReason` is `AI_STOP_CONTENT_FILTER`. Gemini `MALFORMED_FUNCTION_CALL`, `UNEXPECTED_TOOL_CALL` and `TOO_MANY_TOOL_CALLS` finish reasons give `AI_STOP_ERROR`.

## Known Limitations

- The API key is sent in the URL query string (`?key=`), not in the `x-goog-api-key` header. `cdtJsonHttpTransfer` stores the URL with the key in `psLastRequestUrl`, and `psJsonTransferStatus` would include it in its text.
- `pbParallelToolCalls` is ignored.
- `bStrict` on tool definitions isn't used; Gemini's `VALIDATED` mode isn't supported.
- The older `CreateRequest` ignores `piMaxTokens`. It only sends `generationConfig` when `pGenerationConfig.iMaxOutputTokens` is above 0, and then also sends `temperature`, `topP` and `topK`, even when they are 0. It also adds a `"model"` member to the body.
- Text attachments are sent as the content of `uBase64File` as is; put plain text there for text types.
- Generated call ids (`gemini-call-<n>`) are never sent back; results are matched by name and order.
- Streaming is not supported.
