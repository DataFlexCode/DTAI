# cGrokInterface Class Documentation

CAUTION: This document was generated by an AI and has only gone under cursory review. Consult the source if anything here doesn't work or sound right! The example code has not been compiled.

## Overview

The `cGrokInterface` class provides a DataFlex interface to xAI's Grok models. It is part of the DTAI (Datatech AI Library) and inherits from [cAiInterface](cAiInterface.md).

Grok is called on xAI's OpenAI-compatible Chat Completions endpoint (`https://api.x.ai/v1/chat/completions`). Requests are built with the same `cChatGPTRequest` class that [cChatGPTInterface](cChatGPTInterface.md) uses, and responses are read with `cGrokTranslator`, a `cChatGPTTranslator`. The deprecated Anthropic-style `/v1/messages` endpoint is no longer used.

Conversations, tools, the tool loop, confirmation and silent errors are implemented in [cAiInterface](cAiInterface.md).

### Class Properties
- **`psHost`** (String): API endpoint host  
  Default: `"api.x.ai"`

- **`psApiKey`** (String): xAI API key (inherited)  
  Set in `Construct_Object` from `EnvironmentVariable(ghoEnvironment,'grok-api-key')`

## Methods

### Public Methods

#### `AddStandardHeaders String sContentType`
Clears the headers, sets `psContentTypeSent` to `"application/json"` and adds `Cache-Control: no-cache`, `Accept: */*` and `Authorization: Bearer <psApiKey>`. `sContentType` isn't used.

#### `MakeRequestJSON Handle hoRequest Returns Handle`
Sends a request to `v1/chat/completions` and returns the response JSON handle (the caller destroys it), or 0.

**Implementation:**
- Checks the API key first (`AI_ERR_NO_API_KEY`)
- Sends `SetTimeout 45`: the WinINet receive timeout is set to 45 seconds, because Grok models reason by default and can be slow. The setting is process-wide.

**Error Handling:**
- Transfer failures: `ReportAIError AI_ERR_TRANSFER`, caption "Transfer failed!". When the reply was `text/plain`, the text is first shown in an `Info_Box` "Text Response" (only when `pbSilentErrors` is False).
- Error responses in both styles are reported as `AI_ERR_API`:
  - xAI style `{"code":"...","error":"..."}`: the message is `error`, the caption is `code`;
  - OpenAI style `{"error":{"message":"...","type":"..."}}`: the message is `error.message`, the caption is `error.type`;
  - "API Error" when there is no code or type.
- Null members are removed from the response

#### `MakeRequest Handle hoRequest Returns tAIResponse`
Sends a request built by `CreateRequest` and returns the unified response. Stores the request and response JSON in `psModelRequestJson`/`psModelResponseJson`. On failure `eStopReason` is `AI_STOP_ERROR`.

#### `CreateRequest String sPrompt tAIAttachment[] Attachments Returns Handle`
Builds a single-prompt request in Chat Completions format with `ConstructConversationRequest` of `oGrokRequest`: one user message with the optional attachments, no tools and no system prompt.

#### `ModelList Returns tAIModel[]`
Calls `v1/models`. `id`, `display_name` (= id) and `type` are filled. Cached in `paModels`.

#### `ProviderName Returns String`
Returns `"grok"`.

### Conversation and Tool Methods

Inherited from [cAiInterface](cAiInterface.md): `Chat`, `ContinueConversation`, `AddTool`, `SetToolChoice`, `ApproveToolCall`, `DeclineToolCall`, the tool events and `OnAIError`.

#### `BuildConversationRequest tAIMessage[] Messages tAIToolDefinition[] Tools Returns Handle`
`ConstructConversationRequest` of `oGrokRequest` with `psModelId`, `piMaxTokens`, the messages, the tools, `EffectiveSystemPrompt`, `peToolChoice`, `psToolChoiceName` and `pbParallelToolCalls`.

#### `ParseConversationResponse Handle hoResponse Returns tAIResponse`
Removes null members and calls `TranslateConversationResponse` of `oGrokTranslator`.

## Tool Call Mapping

The mapping is the same as for [cChatGPTInterface](cChatGPTInterface.md#tool-call-mapping), with these differences:

- PDFs are skipped (no `file` parts), because `pbFileParts` is False. Images are sent as `image_url` data URIs; text and JSON attachments as text parts.
- `max_tokens` is always used, never `max_completion_tokens` or `reasoning_effort`.

In short:

| Neutral | Grok request |
|---|---|
| System prompt | First message with role `system` |
| `tAIToolDefinition` | `{"type":"function","function":{"name","description","parameters"}}` (+ `strict`) |
| Tool choice | `auto` not sent; `"none"`, `"required"`, or `{"type":"function","function":{"name":...}}` |
| `pbParallelToolCalls` False | `"parallel_tool_calls": false` |
| Assistant turn | `content` and `tool_calls` rebuilt from the neutral form |
| Tool results | One `role: "tool"` message per result with `tool_call_id`; errors as `{"error":"..."}` |

Response: `tool_calls` become `tAIToolCall`; `finish_reason` maps as for ChatGPT.

## Usage Examples

### A chat

```dataflex
Use grokai.pkg

Procedure AskGrok
    tAIResponse Response
    Set pbSilentErrors of ghoGrokAI to True
    Get Chat of ghoGrokAI "Explain recursion with a short DataFlex example." to Response
    If (HasError(ghoGrokAI)) Showln ("Error: " + psLastError(ghoGrokAI))
    Else Showln Response.sText
End_Procedure
```

### A tool that requires confirmation

```dataflex
Procedure SendReminderWithGrok
    tAIResponse Response
    Integer i
    Send AddTool of ghoGrokAI "send_reminder" "Sends a reminder email to a customer." ;
        '{"type":"object","properties":{"customer_id":{"type":"integer"}},"required":["customer_id"]}' True
    Set phoToolHandler of ghoGrokAI to oReminderTools   // your handler object with OnToolCall
    Set pbSilentErrors of ghoGrokAI to True             // defer confirmation to the app

    Get Chat of ghoGrokAI "Remind customer 17 about the unpaid invoice." to Response
    If (Response.eStopReason = AI_STOP_CONFIRMATION) Begin
        For i from 0 to (SizeOfArray(Response.PendingConfirmations) - 1)
            Send DeclineToolCall of ghoGrokAI Response.PendingConfirmations[i].sId "Not during the holidays."
        Loop
        Get ContinueConversation of ghoGrokAI to Response
    End
    Showln Response.sText
End_Procedure
```

### Choosing a model from the list

```dataflex
Procedure ShowGrokModels
    tAIModel[] Models
    Integer i
    Get ModelList of ghoGrokAI to Models
    For i from 0 to (SizeOfArray(Models) - 1)
        Showln Models[i].id
    Loop
End_Procedure
```

## Environment Setup

### API Key Configuration

The key is read from `ghoEnvironment` with the name `'grok-api-key'` when the object is created:

1. Add `grok-api-key={your key}` to the `{program}.env` file in the program folder, or
2. Set the Windows environment variable `grok-api-key`, or
3. `Set psApiKey of ghoGrokAI to sKey` from your own settings.

Never put API keys in source code.

### Model Configuration

```dataflex
Set psModelId of ghoGrokAI to "grok-4.7"
Set piMaxTokens of ghoGrokAI to 32000
```

## Error Handling

All errors go through `ReportAIError` (see [cAiInterface](cAiInterface.md#silent-errors)). `psLastErrorDetail` holds the xAI `code` or OpenAI-style `type`, and `piLastHttpStatus` the HTTP status. With `pbSilentErrors` True nothing is shown.

## Known Limitations

From the source and `tool_calls_plan.md`:

- Grok accepts PDFs only by URL. The class doesn't send PDF attachments.
- xAI requires a tool `description` and a `parameters` root that is an object (or `anyOf`/`oneOf` of objects); otherwise the API returns a 400 error naming the tool.
- Up to 350 tools are allowed on Chat Completions.
- Grok models reason by default and can be slow; `MakeRequestJSON` sets a 45-second receive timeout for the whole process.
- `ModelList` reads the list into `tClaudeModel` structs, so `created` and `owned_by` are not filled.
- With `pbSilentErrors` False, a `text/plain` failure shows two boxes: the text, then the transfer error.
- `piMaxTokens` defaults to 256000; lower it if a model rejects that value.
- Text attachments are sent as the content of `uBase64File` as is; put plain text there for text types.
- Streaming and the Responses API are not supported.
